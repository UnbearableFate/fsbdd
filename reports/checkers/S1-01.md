# Checker Report：S1-01/harden2-a57a5cb-2384525

## Verdict

Phase A：`NOT_REQUIRED`

Phase B：`BLOCKED`

The built-in GPT-NeoX/LLaMA maps, ordinary tied-weight ownership, misc-byte
selection, and selected real Pythia-160m report are internally consistent.
Closure is nevertheless blocked by two fail-closed gaps in the production
registry API:

1. `ExplicitMapping` bypasses the encoder-decoder exclusion. The only
   `config.is_encoder_decoder` check is inside `_builtin_mapping()`, while
   `build_logical_layer_registry()` selects `explicit or _builtin_mapping(model)`.
   Therefore an otherwise fully covered model with
   `config.is_encoder_decoder=True` is accepted whenever an explicit mapping is
   supplied. This directly violates `MODEL-01`; explicit mapping under
   `MODEL-06` is not permission to expand the supported model scope.
2. The registry never inspects or classifies buffers. An explicitly mapped
   decoder-only structure containing a persistent mutable training-semantic
   buffer can report `owned == unique_trainable`, `unowned == 0`, and apparent
   100% coverage while the buffer has neither an ownership rule nor an explicit
   rejection. `MODEL-05` requires such a buffer to be specified before that
   model is supported.

Both cases silently return a successful registry, so they are requirement
failures rather than optional hardening follow-ups.

## 代码与协议检查

- scope：the diff adds only the model registry, a real-HF structural summary,
  focused fixtures/tests, documentation and evidence persistence. It does not
  implement fragment partitioning, payload publication, training, topology,
  stale policy or outer optimization and does not change dependencies/Torch.
- forward order：the two built-ins reconstruct the intended order as
  `gpt_neox.embed_in -> gpt_neox.layers.0..N-1 -> embed_out` and
  `model.embed_tokens -> model.layers.0..N-1 -> lm_head`. `named_children()`
  supplies official HF `ModuleList` order. Final norm is correctly represented
  as misc state adjacent to the last block and head. Explicit mappings take
  `block_paths` order from the caller; the registry makes that order visible
  but cannot derive execution order from an arbitrary `forward()`.
- tied ownership：all trainable aliases are grouped by Python parameter-object
  identity. When an object appears below both embedding and head paths it has
  one registry record owned by `embedding`, retains both aliases, and is listed
  in `tied_identities`; any sharing involving another logical layer fails.
  Unique head parameters remain owned by `lm_head`. The real Pythia revision is
  untied, so its empty `tied_identities` plus distinct embedding/head weights
  is expected rather than missing tied evidence.
- misc ownership：built-in final norms name the actual adjacent layers. The
  implementation compares synchronization bytes and selects left on `<=`, so
  a tie goes to the earlier layer. Selected-side bytes are then updated. The
  Pythia report records last-block/head bytes of `28,351,488/154,533,888` before
  assignment and assigns the 1,536-parameter final norm to block 11.
- coverage：unowned trainable parameter objects and unsupported cross-layer
  sharing raise. Successful registries create one record per unique trainable
  Python object and separately validate record-identity uniqueness. This proves
  parameter-to-logical-owner coverage, not parameter-to-fragment coverage.
- fail-closed model scope：blocked. `_builtin_mapping()` rejects
  `is_encoder_decoder`, but supplying `explicit` bypasses that function and
  reaches a successful registry.
- buffers：blocked. `_global_aliases()` enumerates only `named_parameters()`;
  neither `named_buffers()` nor an explicit static/mutable buffer policy is
  consulted. Coverage fields therefore cannot expose an unsupported mutable
  training-semantic buffer.
- data plane / bounded state / atomic publication / base-consumption /

  Registry objects and reports are finite. The selected run binds code, config,
  source, skill, execution, roles and paths; formula identity is not applicable.

## Independent DP and counterexample check

The two DP stages have valid optimal substructure. For a state ending at layer
`end` after `k` nonempty fragments, every predecessor cut is enumerated. The
first recurrence minimizes the maximum of the predecessor cap and final
segment sum. After freezing that cap, future feasibility and cost depend only
on `(k,end)`; the second recurrence can therefore retain the minimum pair
`(accumulated scaled deviation, cut tuple)`. Python tuple order implements the
required secondary then earlier-cut order. Nonnegative integer weights also
make `sum(weights)+1` a sound unreachable sentinel.

Independent finite checks agree with the intended objective:

1. Primary greedy failure: for bytes `(1,5,1,4)`, `F=3`, cuts `(1,2)` produce
   `(1,5,5)` with maximum `5`; the other cuts produce maximum at least `6`.
2. Secondary-before-tertiary case not listed by the Maker: for
   `(0,0,1,1,2)`, `F=3`, the minimax cap is `2`. Cuts `(1,4)` or `(2,4)`
   produce `(0,2,2)` with scaled deviation `8`, while cuts `(3,4)` produce
   `(1,1,2)` with scaled deviation `4`; the later first cut must win because
   the secondary objective precedes the front-cut tie break.
3. Pure tie: for `(1,1,1,1,1)`, `F=2`, cuts `2` and `3` both produce the
   same maximum `3` and scaled deviation `2`; cut `2` is correctly chosen.
4. Oversized layer: `(2,2,50,2,2)`, `F=3` has a feasible cap `50` only when
   the `50`-byte layer is a complete singleton; splitting it is impossible.
5. The recorded exhaustive count is internally correct:
   `(6^3-1)*1 + (6^4-1)*2 + (6^5-1)*3 + (6^6-1)*4 = 212750`.
   The analyzer enumerates all cut combinations through ten partitions per
   case and reports zero mismatch, plus 500 seeded cases through 12 layers.

The builder consequently emits the right objective. The blocker is not the DP
recurrence; it is the missing validation link between that objective and the
map's actual fragments.

## Maker-unlisted surviving counterexamples

### 1. Non-optimal actual cuts with an optimal decoy objective

Start from the valid registry with layer bytes `(1,5,1,4)` and `F=3`. Construct
three complete, contiguous fragments using cuts `(1,3)`, so actual fragment
bytes are `(1,6,4)` and the actual maximum is `6`. Keep the independently
optimal objective from the same registry: cuts `(1,2)`, maximum `5`, scaled
deviation `16`. Give the map a canonical balance summary for its actual
`(1,6,4)` fragments and recompute the map digest.

Static control-flow inspection shows that `validate_fragment_map()` accepts
this object:

- the intervals and parameter partition are complete and contiguous;
- `expected_objective == fragment_map.objective` is true because the decoy
  objective is the correct optimum;
- the balance checks pass because they are recomputed from the non-optimal
  actual fragments;
- no branch compares actual exclusive ends to `objective.cut_indices`, actual
  maximum to `objective.maximum_sync_bytes`, or actual scaled deviation to
  `objective.total_deviation_scaled`.

Thus a digest-valid map accepted by the designated checker violates
`FRAG-05/A-FRAG-03`.

### 2. Synchronization-dtype field can diverge from the registry

Take any valid map, change only its top-level `sync_dtype_bytes`, and recompute
its digest. The validator binds `registry_digest`, layer summaries, fragment
byte sums and the objective, but never checks
`fragment_map.sync_dtype_bytes == registry.sync_dtype_bytes`. The map therefore
passes while its report has two conflicting synchronization-byte semantics.
The builder itself copies the correct value; the defect is again in the
authority checker and affects `FRAG-04/FRAG-08` self-consistency.

### 3. Frozen evidence paths do not resolve

All eleven matrix rows point under `runtime_runs/S1-02/formal/...`, but no such
selected tree exists. The finalized authority is
`runtime_runs/S1-02/harden-4e696a3-2384543/...`. The evidence index repairs the
human-facing link, but the frozen row-level contract remains non-resolvable and
several named leaf paths (`analysis/fragment-map.json`) do not match any
selected file. This is a persistence/traceability defect rather than an
algorithmic one.

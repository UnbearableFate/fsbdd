## GREEN and hardening

The production kernel streams immutable selected contribution files in frozen
order through one live local payload lease. It computes fp32
`weight * (declared_base - local)` into a fragment accumulator, resolves an old
base only for the contribution that declared it, then applies a per-fragment
SGD state transition at current parameters. The explicit default is a
pluggable direct-weighted-average policy. Updated-buffer Nesterov, momentum-free
control, fragment-state isolation, exact byte accounting, and canonical update
identity are fail-closed.

The selected formal run independently reconstructs 50 Stage 0 oracle
transitions. Maximum parameter relative L2 is
`2.114216746296519e-9`; the first-ten maximum is
`1.3233751054520785e-10`, the last-ten maximum is zero, and all 50 update
identities are distinct. All 16 deterministic contribution permutations have
zero relative L2 difference. The declared-old-base fixture produces exactly
`[9,-5]`; the prohibited current-relative surrogate produces `[4.5,-1.5]`
with relative L2 `0.5537181355029882`.

The 4 MiB M=1 and M=8 target updates each peak 9 MiB above their identically
warmed entry RSS, so M=8 minus M=1 is zero against the 12 MiB gate. Both retain
one local payload lease and at most three fragment payloads in the tensor
ledger. M=1 reads exactly 4 MiB and M=8 exactly 32 MiB of local payloads; each
has one 4 MiB current input and one 4 MiB successor. No operation requests or
accounts the 16 MiB full model.

Both application roles report zero current-PID GPU memory before and after the
workload. The scheduler separately records a 2 MiB validation-plane peak on

## RED and correction history

The two original semantic RED surrogates exit 1 before production storage is
implemented. The S1-03 surrogate rejects a listing-capable interface and an
invalid partial payload; the reused S0B-02 unsafe direct-overwrite fixture
records 5,208 partial or torn observations.

The first two-node package, `runtime_runs/S1-03/formal-l2`, is preserved but
rejected for selection. Its application results passed, but an unzoned local
PBS `qtime` was mislabeled as UTC. The exact regression then failed against the
old parser (SHA-256 `448eec57...1e7d`). The corrected script explicitly parses
JST before producing UTC; the L1 preflight converts `Wed Jul 15 08:13:21 2026`
to `2026-07-14T23:13:21Z`, passes all 68 Stage 1 tests, and is validator-
admissible (manifest `eaae119c...d0e4`). The same Checker context readmitted the
replacement L2 run.

## GREEN and hardening

`StorageBackend` exposes only fixed-slot `publish` and `read`. The POSIX
implementation writes a unique immutable payload, reads it back to verify size
and SHA-256, stages a complete small JSON record, and makes that record visible
with `os.replace`. Reads open exactly one visibility record and its referenced
payload, validate every bound identity field, and never scan payload history.

The selected two-node run publishes 500 compound 128-KiB payloads while the
reader continuously polls across the common publication interval. It records
1,428 valid observations, all 501 sequences including bootstrap and final
sequence 500, zero invalid reads, and zero directory/history scans. The four
crash points produce old/old/old/complete-new. Writer and reader run on two
distinct allocated hosts. All 68 Stage 1 tests and 9/9 requirement rows pass;
all stderr logs are empty.

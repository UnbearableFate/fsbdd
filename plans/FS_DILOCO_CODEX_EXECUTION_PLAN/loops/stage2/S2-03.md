| 9 节点门禁 | 强制：见本卡 Miyabi Final Gate 节与 `docs/06_8L1S_50X10_GATE.md` |

## 单一目标

在FS限速、发布/采用滞后时保证pending、in-flight、temp、orphan与GC backlog有界，训练优先。

## 非目标

- 不让GC进入correctness路径
- 不保存历史proposal
- 不通过阻塞learner解决背压

## ORIENT 与 PREFLIGHT

通用 ORIENT/PREFLIGHT 要求见 `AGENTS.md` §4.1、`docs/03_LOOP_ENGINEERING_PROTOCOL.md` 与 `templates/LOOP_CARD.md`，不在此重复；ORIENT 或 PREFLIGHT 不完整时不得进入 RED。本 loop 进入 RED 前必须额外冻结：

- requirement matrix 覆盖 LEARN-06、PERF-03/05、FS-06/09；
- 有界性指标定义：queue depth/temp bytes/live bytes 的采样点与频率，发散判定公式；
- 1/10 限速注入机制与其验证方法；2h run 与 gate run 的双重用途预注册（提交前）。

## SPECIFY / RED

- 1/10 FS模拟下naive queue持续增长并触发bound assertion。
- old pending snapshot未被替换、temp无上限、GC失败中断训练的fixtures失败。
- history扫描型GC随update增长被复杂度test拒绝。

## IMPLEMENT / GREEN

- latest-wins pending、单in-flight、skip counters。
- 固定retention和异步GC；GC失败告警。
- 暴露queue/temp/live bytes metrics和hard caps。

## HARDEN

- 至少2h slow-FS stage run；短9N overlay采用1/10限速。
- kill publisher留下orphan；restart/GC。
- quota-near warning，no correctness impact。

## Miyabi Final Gate

强制：按 `docs/06` 提交新的 8+1/50×10 run（1/10 FS 限速 overlay）。若 ≥2h slow-FS stage run 本身以 9 节点 8+1 拓扑、限速 overlay 完成 50×10 且提交前预注册为双重用途，则同一 run 同时充当本 loop gate；否则 gate 与 2h run 分开提交。

## CHECK

- Checker画queue/time趋势并检查无单调发散。
- 9N gate在限速overlay下仍完成50×10、loss下降。

## PERSIST 输出

- backpressure/GC implementation
- 2h slow-FS evidence
- A-PERF-02 report
- new 9N gate package

另按 `AGENTS.md` §7 更新 PROGRESS、traceability、evidence index、checksums 与 compact handoff。

## 完成定义与停止条件

完成定义见 `AGENTS.md` §7（RED 有效、GREEN/HARDEN 通过、适用 gate 通过、Checker 允许关闭、证据/进度/handoff 持久化）。达到以下条件即停止，不为额外置信度追加运行或重构：

- 限速下 queue/temp/GC backlog 全部有界、≥2h run 与 gate run（可为同一 run）通过即关闭；
- GC 不进入 correctness 路径；不通过阻塞 learner 解决背压。

## 单一目标

在不改算法语义的前提下达到160M和0.5–1B GPU goodput≥95%、snapshot+adoption pause≤2%，完成性能分解和Stage2关闭。

## 非目标

- 不引入多syncer/压缩
- 不为了性能跳过校验
- 不改变H/Q等比较条件

## ORIENT

Codex 在修改前必须落盘：

- 当前 source spec hashes、branch/base commit 与 dirty state；
- 前置 loops 和 acceptance 是否有可复算证据；
- 当前唯一 failing gap；
- 预计修改文件与不会修改的接口；
- 本 loop 的资源、walltime、model/data/config；
- 适用时 compatible 9N baseline ID、loss/runtime阈值和fault/heterogeneity overlay；
- `miyabi-development` commit 与 host routing（涉及 Miyabi 时）。

ORIENT 结果不完整时不得进入 RED。

## SPECIFY / RED

- 建立no-communication local baseline和当前FS path；未达阈值先RED。
- byte accounting出现full model transfer时失败。
- 若提出多syncer但无具体bottleneck profile，PERF-06 checker失败。

保存失败命令、exit code、fixture/config、seed、stdout/stderr。RED 必须在错误或缺失实现上确实失败。

## IMPLEMENT / GREEN

- 基于profile做最小优化：buffer reuse、poll cadence、I/O chunk、CPU affinity等，逐项开关。
- 实现visibility-delay injection接口并证明不改变correctness。
- 冻结性能profile。

只修当前 RED；额外重构或新策略拆成后续 loop。

## HARDEN

- 160M、0.5–1B各跑；冷/热cache条件一致。
- pause、goodput、CPU/FS成本、latency decomposition。
- 回归slow FS有界。

低层检查未通过时不上更大拓扑。

## Miyabi Final Gate

强制：本 loop 结束前提交新的 Miyabi 8 learners + 1 syncer、9 distinct compute nodes、H=50、target_global_cycles=10 run；loss/runtime/topology/protocol gates 全部通过。

适用时按 `docs/06_8L1S_50X10_GATE.md` 产生新的、不可复用的 run package。队列等待不计 active runtime；所有阈值在提交前冻结。

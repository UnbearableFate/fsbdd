## 单一目标

实现可重算的learner/syncer/storage/algorithm结构化指标和端到端snapshot/write/discovery/read/adopt分解；telemetry不参与correctness。

## 非目标

- 不让metrics决定commit
- 不只打印人类日志
- 不改变算法

## ORIENT

Codex 在修改前必须落盘：

- 当前 source spec hashes、branch/base commit 与 dirty state；
- 前置 loops 和 acceptance 是否有可复算证据；
- 当前唯一 failing gap；
- 预计修改文件与不会修改的接口；
- 本 loop 的资源、walltime、model/data/config；
- 适用时 compatible 9N baseline ID、loss/runtime阈值和fault/heterogeneity overlay；
- `miyabi-development` commit 与 host routing（涉及 Miyabi 时）。

ORIENT 结果不完整时不得进入 RED。

## SPECIFY / RED

- 关闭telemetry后协议仍应正确；依赖metric才能前进的fixture失败。
- 缺关键event或时间不单调时analyzer失败。
- 用伪造汇总而无raw events时evidence checker失败。

保存失败命令、exit code、fixture/config、seed、stdout/stderr。RED 必须在错误或缺失实现上确实失败。

## IMPLEMENT / GREEN

- per-role JSONL schemas、event IDs、monotonic spans。
- 实现loss/runtime/topology/protocol gate analyzer。
- 生成latency breakdown、staleness/weights/rejections/bytes/queue图表数据。

只修当前 RED；额外重构或新策略拆成后续 loop。

## HARDEN

- 日志丢失/截断/重复event，analyzer显式标记不完整。
- 高频metrics开销测量和sampling策略。
- 9N全角色trace可join。

低层检查未通过时不上更大拓扑。

## Miyabi Final Gate

强制：本 loop 结束前提交新的 Miyabi 8 learners + 1 syncer、9 distinct compute nodes、H=50、target_global_cycles=10 run；loss/runtime/topology/protocol gates 全部通过。

适用时按 `docs/06_8L1S_50X10_GATE.md` 产生新的、不可复用的 run package。队列等待不计 active runtime；所有阈值在提交前冻结。

Checker 使用新上下文和 `templates/CHECKER_REPORT.md`，不得仅复述 Maker 结论。

## 单一目标

把fragment snapshot复制到有界CPU staging并由后台worker写FS，使GPU inner training在copy安全边界后立即继续。

## 非目标

- 不实现adoption优化
- 不扩大queue
- 不改proposal语义

## ORIENT

Codex 在修改前必须落盘：

- 当前 source spec hashes、branch/base commit 与 dirty state；
- 前置 loops 和 acceptance 是否有可复算证据；
- 当前唯一 failing gap；
- 预计修改文件与不会修改的接口；
- 本 loop 的资源、walltime、model/data/config；
- 适用时 compatible 9N baseline ID、loss/runtime阈值和fault/heterogeneity overlay；
- `miyabi-development` commit 与 host routing（涉及 Miyabi 时）。

ORIENT 结果不完整时不得进入 RED。

## SPECIFY / RED

- timing test证明同步FS写占用训练主线程；作为RED。
- 后台异常被吞掉、无限queue、mutable staging payload的fixtures失败。
- snapshot完成前GPU参数继续mutation导致payload不稳定的test失败。

保存失败命令、exit code、fixture/config、seed、stdout/stderr。RED 必须在错误或缺失实现上确实失败。

## IMPLEMENT / GREEN

- 使用明确CUDA stream/event或安全copy策略；CPU buffer数量有界。
- 每fragment最多一个in-flight publication，pending latest-wins。
- 后台结果/错误通过typed channel反馈；训练不等FS。

只修当前 RED；额外重构或新策略拆成后续 loop。

## HARDEN

- slow writer、large fragment、skip/replacement、shutdown。
- 1-node profile snapshot/copy；2-node真实FS。
- 比较同步基线与异步step time。

低层检查未通过时不上更大拓扑。

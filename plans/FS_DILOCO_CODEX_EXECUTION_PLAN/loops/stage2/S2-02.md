# S2-02：异步 FS→CPU→GPU Adoption Pipeline

## 元数据

| 字段 | 值 |
|---|---|
| Stage | stage2 |
| 前置 loops | S2-01 |
| 规范条款 | LEARN-08, PERF-02, PERF-03, PERF-05, TEL-01 |
| Acceptance | 本 loop 为后续 acceptance 提供组成证据 |
| 最高资源级别 | Miyabi 1/2/9 nodes |
| 9 节点门禁 | 强制：见本卡 Miyabi Final Gate 节与 `docs/06_8L1S_50X10_GATE.md` |

## 单一目标

后台发现/读取/校验最新global fragment，在安全边界进行有限CPU→GPU覆盖，允许跳过中间版本并保持训练。

## 非目标

- 不改变adoption语义
- 不重置moments
- 不等待全fragment

## ORIENT 与 PREFLIGHT

通用 ORIENT/PREFLIGHT 要求见 `AGENTS.md` §4.1、`docs/03_LOOP_ENGINEERING_PROTOCOL.md` 与 `templates/LOOP_CARD.md`，不在此重复；ORIENT 或 PREFLIGHT 不完整时不得进入 RED。本 loop 进入 RED 前必须额外冻结：

- requirement matrix 覆盖 LEARN-08、PERF-02/03/05、TEL-01；
- pause 测量定义：safe-boundary copy/apply 的单调钟 span，分母为 active runtime，聚合用共同区间；
- 单元 gate run 的双断言 analyzer（overlap+pause）在提交前实现并用假数据 RED。

## SPECIFY / RED

- 主线程同步FS read造成pause的timing RED。
- pending多个版本未latest-wins导致queue增长。
- apply发生在backward/optimizer mutation中间时参数一致性test失败。

## IMPLEMENT / GREEN

- 后台poll/read/verify到有界CPU staging。
- 每fragment只保留最新pending adoption。
- 安全boundary短暂停copy/apply，更新base/counters。

## HARDEN

- global快速连续更新、read延迟、corrupt newest后保留旧合法state。
- in-flight proposal并存；mixed-version。
- pause分解与GPU同步点profile。

## Miyabi Final Gate

强制，且为 `GU-S2-ASYNC` 单元 gate：按 `docs/06` 提交一次新的 8+1/50×10 run，analyzer 同时断言 S2-01 upload overlap 与本 loop adoption pause；其余 gate 条件不变。run 失败且根因涉及 S2-01 时两个 loop 一并重开。

## CHECK

- Checker检查只有目标fragment和counters变化。
- 9N gate比较pause占比、loss。

## PERSIST 输出

- async adoption
- pause trace
- latest-only tests
- new 9N gate package

另按 `AGENTS.md` §7 更新 PROGRESS、traceability、evidence index、checksums 与 compact handoff。

## 完成定义与停止条件

完成定义见 `AGENTS.md` §7（RED 有效、GREEN/HARDEN 通过、适用 gate 通过、Checker 允许关闭、证据/进度/handoff 持久化）。达到以下条件即停止，不为额外置信度追加运行或重构：

- adoption pause 断言通过、latest-wins pending 有界、GU-S2-ASYNC 单元 gate run 通过即关闭（同时关闭 S2-01 gate 义务）；
- 不改变 adoption 语义、不重置 moments。

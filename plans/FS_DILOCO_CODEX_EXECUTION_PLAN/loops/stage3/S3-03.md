## 单一目标

在payload写入、payload完成、visibility替换前/后等点kill syncer，重启后只观察旧完整或新完整state，永无半提交。

## 非目标

- 不要求清除所有orphan后才恢复
- 不做存储级事务
- 不扩展为exact replay

## ORIENT

Codex 在修改前必须落盘：

- 当前 source spec hashes、branch/base commit 与 dirty state；
- 前置 loops 和 acceptance 是否有可复算证据；
- 当前唯一 failing gap；
- 预计修改文件与不会修改的接口；
- 本 loop 的资源、walltime、model/data/config；
- 适用时 compatible 9N baseline ID、loss/runtime阈值和fault/heterogeneity overlay；
- `miyabi-development` commit 与 host routing（涉及 Miyabi 时）。

ORIENT 结果不完整时不得进入 RED。

## SPECIFY / RED

- 逐阶段fault hooks；unsafe分离records实现至少一个点出现混合state并失败。
- publication前consumed生效的fixture失败。
- orphan存在时reader误发现的fixture失败。

保存失败命令、exit code、fixture/config、seed、stdout/stderr。RED 必须在错误或缺失实现上确实失败。

## IMPLEMENT / GREEN

- 完善fault injection hooks与restart verifier。
- current record作为唯一authority；temp/orphan不被discovery。
- GC异步回收。

只修当前 RED；额外重构或新策略拆成后续 loop。

## HARDEN

- 每个kill点重复；reader并发；FS visibility delay。
- params/outer/version/frontier/content identity全组合校验。
- old/new合法结果计数。

低层检查未通过时不上更大拓扑。

## Miyabi Final Gate

强制：本 loop 结束前提交新的 Miyabi 8 learners + 1 syncer、9 distinct compute nodes、H=50、target_global_cycles=10 run；loss/runtime/topology/protocol gates 全部通过。

适用时按 `docs/06_8L1S_50X10_GATE.md` 产生新的、不可复用的 run package。队列等待不计 active runtime；所有阈值在提交前冻结。

## CHECK

- Checker不信任汇总，直接检查storage snapshot与records。
- 9N gate预注册一个/多个kill点，恢复后完成cycle10。

Checker 使用新上下文和 `templates/CHECKER_REPORT.md`，不得仅复述 Maker 结论。

## PERSIST 输出

- crash matrix harness
- storage snapshots
- A-REC-03 report
- new 9N fault gate

另必须更新：

- `plans/PROGRESS.yaml`
- `plans/ACCEPTANCE_TRACEABILITY.csv`
- loop evidence index/checksums
- 下一最小 failing gap

## 完成定义

- RED 在错误实现上失败；
- GREEN 与 HARDEN 全通过；
- 本 loop 相关 requirement 未被隐式改写；
- 适用时新的 9N 50×10 门禁通过；
- Checker 为 `PASS` 或允许关闭的 `PASS_WITH_FOLLOWUPS`；
- 证据、config、commit 与进度已持久化；
- 没有未登记 blocker。

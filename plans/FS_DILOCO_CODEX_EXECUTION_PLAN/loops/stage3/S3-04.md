# S3-04：Quorum Availability Boundary、Automatic Resume 与 Stage 3 关闭

## 元数据

| 字段 | 值 |
|---|---|
| Stage | stage3 |
| 前置 loops | S3-03 |
| 规范条款 | REC-04, INV-01, SYNC-05 |
| Acceptance | A-REC-04 |
| 最高资源级别 | Miyabi independent 9-node jobs |
| 9 节点门禁 | 强制：本 loop 结束前提交新的 Miyabi 8 learners + 1 syncer、9 distinct compute nodes、H=50、target_global_cycles=10 run；loss/runtime/topology/protocol gates 全部通过。 |

## 单一目标

当某fragment eligible learners<Q时只停止该fragment，其他fragments与learners继续；learner恢复后无人工修改自动续，并完成Stage3全矩阵。

## 非目标

- 不改变Q
- 不把quorum不足当系统错误
- 不做dynamic membership

## ORIENT

Codex 在修改前必须落盘：

- 当前 source spec hashes、branch/base commit 与 dirty state；
- 前置 loops 和 acceptance 是否有可复算证据；
- 当前唯一 failing gap；
- 预计修改文件与不会修改的接口；
- 本 loop 的资源、walltime、model/data/config；
- 适用时 compatible 9N baseline ID、loss/runtime阈值和fault/heterogeneity overlay；
- `miyabi-development` commit 与 host routing（涉及 Miyabi 时）。

ORIENT 结果不完整时不得进入 RED。

## SPECIFY / RED

- kill足够learners使一个fragment不足Q；全局/全部fragments若一起停则失败。
- 恢复learner后需手工清理/重置才能继续则失败。
- learner主训练因syncer停而阻塞则失败。

保存失败命令、exit code、fixture/config、seed、stdout/stderr。RED 必须在错误或缺失实现上确实失败。

## IMPLEMENT / GREEN

- 确保per-fragment readiness独立；等待状态非busy loop。
- 角色恢复后latest proposal自动进入固定slots。
- availability/ready queue telemetry。

只修当前 RED；额外重构或新策略拆成后续 loop。

## HARDEN

- 不同fragment offsets/eligible sets；反复失去/恢复quorum。
- Stage3要求的10次syncer kill、learner recovery与publication matrix汇总。
- 9N independent run在故障后完成10cycles。

低层检查未通过时不上更大拓扑。

## Miyabi Final Gate

强制：本 loop 结束前提交新的 Miyabi 8 learners + 1 syncer、9 distinct compute nodes、H=50、target_global_cycles=10 run；loss/runtime/topology/protocol gates 全部通过。

适用时按 `docs/06_8L1S_50X10_GATE.md` 产生新的、不可复用的 run package。队列等待不计 active runtime；所有阈值在提交前冻结。

## CHECK

- Checker检查其他fragment真实outer count前进而非仅heartbeat。
- 完成Stage3 checkpoint和全部REC acceptance。

Checker 使用新上下文和 `templates/CHECKER_REPORT.md`，不得仅复述 Maker 结论。

## PERSIST 输出

- quorum scenario trace
- A-REC-04 evidence
- Stage3 full matrix/checkpoint
- new 9N fault gate

另必须更新：

- `plans/PROGRESS.yaml`
- `plans/ACCEPTANCE_TRACEABILITY.csv`
- loop evidence index/checksums
- 下一最小 failing gap

## 完成定义

- RED 在错误实现上失败；
- GREEN 与 HARDEN 全通过；
- 本 loop 相关 requirement 未被隐式改写；
- 适用时新的 9N 50×10 门禁通过；
- Checker 为 `PASS` 或允许关闭的 `PASS_WITH_FOLLOWUPS`；
- 证据、config、commit 与进度已持久化；
- 没有未登记 blocker。

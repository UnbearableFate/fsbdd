# S3-02：Syncer Kill-Restart from Per-fragment Authority

## 元数据

| 字段 | 值 |
|---|---|
| Stage | stage3 |
| 前置 loops | S3-01 |
| 规范条款 | REC-02, FS-10, SYNC-02, GLOBAL-02 |
| Acceptance | A-REC-01 |
| 最高资源级别 | Miyabi independent 9-node jobs |
| 9 节点门禁 | 强制：见本卡 Miyabi Final Gate 节与 `docs/06_8L1S_50X10_GATE.md` |

## 单一目标

syncer仅读取各fragment current records恢复params/outer state/version/consumed frontier，忽略不匹配proposal并继续。

## 非目标

- 不做event replay
- 不做leader election/failover
- 不恢复volatile grace精确时间

## ORIENT 与 PREFLIGHT

通用 ORIENT/PREFLIGHT 要求见 `AGENTS.md` §4.1、`docs/03_LOOP_ENGINEERING_PROTOCOL.md` 与 `templates/LOOP_CARD.md`，不在此重复；ORIENT 或 PREFLIGHT 不完整时不得进入 RED。本 loop 进入 RED 前必须额外冻结：

- requirement matrix 覆盖 REC-02、FS-10、SYNC-02、GLOBAL-02；
- 恢复 interval（≤2× 正常 update interval）的测量定义：正常 interval 基线来源、比较窗口；
- GU-S3-CRASH 单元在 PROGRESS.yaml 登记；single-writer guard 的判定方式。

## SPECIFY / RED

- 删除历史log后仍应恢复；依赖log的实现失败。
- 丢失consumed frontier导致重复消费的restart fixture失败。
- 两个可写syncer同时启动必须被运行环境/preflight拒绝。

## IMPLEMENT / GREEN

- 实现syncer recover path和single-writer guard/preflight。
- per-fragment current加载并重建readiness。
- stale/mismatch proposals自然拒绝。

## HARDEN

- 不同fragments版本、grace中kill、publication前kill、连续restart。
- history目录注入大量对象，startup I/O不增长。
- 正常update interval baseline。

## Miyabi Final Gate

本 loop 属于预注册 gate 单元 `GU-S3-CRASH`（S3-02+S3-03）：允许以 2-node 缩小复现证据与 Checker PASS 先关闭本 loop，9N gate 义务由 S3-03 的单元 fault-tape run 一并履行。该 tape 必须包含 syncer kill+restart 并断言“下一成功 update ≤2× 正常 interval”（本 loop）与 publication kill 点行为（S3-03）。run 失败且根因涉及本 loop 时两个 loop 一并重开；单元内不得插入其他实现 loop。

## CHECK

- Checker从current records独立重建预期state。
- 9N gate kill syncer并重启，下一成功update≤2×正常interval。

## PERSIST 输出

- syncer recovery
- restart startup I/O report
- A-REC-01 evidence
- new 9N fault gate

另按 `AGENTS.md` §7 更新 PROGRESS、traceability、evidence index、checksums 与 compact handoff。

## 完成定义与停止条件

完成定义见 `AGENTS.md` §7（RED 有效、GREEN/HARDEN 通过、适用 gate 通过、Checker 允许关闭、证据/进度/handoff 持久化）。达到以下条件即停止，不为额外置信度追加运行或重构：

- 恢复只依赖 current records、restart I/O 有界、双 syncer 被 preflight 拒绝即关闭；
- 9N gate 义务由 GU-S3-CRASH 在 S3-03 关闭；不做 event replay/leader election。

## 启动指令（新 session 恢复入口）

```text
前置 S3-01 PASS。分支 codex/S3-02-syncer-restart。
目标：syncer 仅读 per-fragment current records 恢复全部状态并继续；忽略不匹配 proposal。
恢复只读：plans/PROGRESS.yaml、本卡、plans/loop_states/S3-02.yaml、S3-01 handoff。
流程：PREFLIGHT（冻结恢复 interval 定义）→ RED（删历史 log 仍恢复/丢 frontier 重复消费/双 syncer 反例）→ GREEN → HARDEN（grace 中 kill、大量假对象注入、连续 restart）→ Checker（从 current records 独立重建）。
资源 ≤ L2；gate 义务由 GU-S3-CRASH 在 S3-03 关闭。PERSIST 后写 compact handoff 并结束 session。
```

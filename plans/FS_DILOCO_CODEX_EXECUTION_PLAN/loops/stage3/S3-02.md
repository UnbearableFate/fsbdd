## 单一目标

syncer仅读取各fragment current records恢复params/outer state/version/consumed frontier，忽略不匹配proposal并继续。

## 非目标

- 不做event replay
- 不做leader election/failover
- 不恢复volatile grace精确时间

## ORIENT

Codex 在修改前必须落盘：

- 当前 source spec hashes、branch/base commit 与 dirty state；
- 前置 loops 和 acceptance 是否有可复算证据；
- 当前唯一 failing gap；
- 预计修改文件与不会修改的接口；
- 本 loop 的资源、walltime、model/data/config；
- 适用时 compatible 9N baseline ID、loss/runtime阈值和fault/heterogeneity overlay；
- `miyabi-development` commit 与 host routing（涉及 Miyabi 时）。

ORIENT 结果不完整时不得进入 RED。

## SPECIFY / RED

- 删除历史log后仍应恢复；依赖log的实现失败。
- 丢失consumed frontier导致重复消费的restart fixture失败。
- 两个可写syncer同时启动必须被运行环境/preflight拒绝。

保存失败命令、exit code、fixture/config、seed、stdout/stderr。RED 必须在错误或缺失实现上确实失败。

## IMPLEMENT / GREEN

- 实现syncer recover path和single-writer guard/preflight。
- per-fragment current加载并重建readiness。
- stale/mismatch proposals自然拒绝。

只修当前 RED；额外重构或新策略拆成后续 loop。

## HARDEN

- 不同fragments版本、grace中kill、publication前kill、连续restart。
- history目录注入大量对象，startup I/O不增长。
- 正常update interval baseline。

低层检查未通过时不上更大拓扑。

## Miyabi Final Gate

强制：本 loop 结束前提交新的 Miyabi 8 learners + 1 syncer、9 distinct compute nodes、H=50、target_global_cycles=10 run；loss/runtime/topology/protocol gates 全部通过。

适用时按 `docs/06_8L1S_50X10_GATE.md` 产生新的、不可复用的 run package。队列等待不计 active runtime；所有阈值在提交前冻结。

- Checker从current records独立重建预期state。
- 9N gate kill syncer并重启，下一成功update≤2×正常interval。

Checker 使用新上下文和 `templates/CHECKER_REPORT.md`，不得仅复述 Maker 结论。

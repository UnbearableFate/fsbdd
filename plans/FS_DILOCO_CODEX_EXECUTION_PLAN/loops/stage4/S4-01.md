## 单一目标

将per-fragment base parameter retention从current-only扩为current+前1版，保持固定窗口、content identity可读和异步GC。

## 非目标

- 不接受stale contribution（下一loop）
- 不支持S_max>1作为必需
- 不保存全历史

## ORIENT

Codex 在修改前必须落盘：

- 当前 source spec hashes、branch/base commit 与 dirty state；
- 前置 loops 和 acceptance 是否有可复算证据；
- 当前唯一 failing gap；
- 预计修改文件与不会修改的接口；
- 本 loop 的资源、walltime、model/data/config；
- 适用时 compatible 9N baseline ID、loss/runtime阈值和fault/heterogeneity overlay；
- `miyabi-development` commit 与 host routing（涉及 Miyabi 时）。

ORIENT 结果不完整时不得进入 RED。

## SPECIFY / RED

- S_max=1时缺old base读取失败；S_max=0时多保留且authority依赖旧base的test失败。
- 经过N updates storage live-set随N线性增长必须失败。
- GC提前删仍可能eligible base的fixture失败。

保存失败命令、exit code、fixture/config、seed、stdout/stderr。RED 必须在错误或缺失实现上确实失败。

## IMPLEMENT / GREEN

- 参数化window size S_max+1；current publication后更新retention。
- base by version/content identity lookup。
- 超窗标记并异步GC，不影响current。

只修当前 RED；额外重构或新策略拆成后续 loop。

## HARDEN

- S_max切换0/1、restart、delayed GC、orphan。
- 100+小update storage bound test。
- 9N S_max=1运行但可保持fresh selection，检查窗口。

低层检查未通过时不上更大拓扑。

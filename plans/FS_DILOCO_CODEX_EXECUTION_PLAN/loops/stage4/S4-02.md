## 单一目标

允许s=1 proposal进入候选并严格使用声明的old base计算 `G^b-L`；拒绝too-stale、missing/future/wrong identity/over-progress。

## 非目标

- 不完成fresh anchor/选择策略
- 不支持S_max>1主路径
- 不改变outer apply point

## ORIENT 与 PREFLIGHT

通用 ORIENT/PREFLIGHT 要求见 `AGENTS.md` §4.1、`docs/03_LOOP_ENGINEERING_PROTOCOL.md` 与 `templates/LOOP_CARD.md`，不在此重复；ORIENT 或 PREFLIGHT 不完整时不得进入 RED。本 loop 进入 RED 前必须额外冻结：

- requirement matrix 覆盖 INV-06/07、STALE-01/04/10、PROP-07；
- 异构注入 profile（速度比、注入方式、期望 s=1 出现率）预注册，不得事后调参；
- displacement 数值对照复用 Stage 0 oracle 错误公式反例，不新造 oracle。

## SPECIFY / RED

- 复用Stage0错误公式反例，production path必须对齐oracle。
- boundary matrix s=0,1,Smax,Smax+1/future。
- missing/wrong content identity和progress cap fixtures。

## IMPLEMENT / GREEN

- eligibility打开S_max=1；lookup exact base payload。
- 统一pseudo-gradient函数；typed rejection reasons。
- 运行时trace记录current/base/staleness/displacement norm。

## HARDEN

- current/base参数明显不同；corrupt base；race中version前进。
- same proposal在选择前变too-stale。
- 9N注入速度差使真实s=1出现。

## Miyabi Final Gate

强制：按 `docs/06_8L1S_50X10_GATE.md` 提交新的、不可复用的 8+1/50×10 run package，loss/runtime/topology/protocol gates 全部通过；阈值提交前冻结，队列等待不计 active runtime。

本 loop 的 gate run 预注册异构注入使真实 s=1 出现；至少有可验证 s=1 候选（不得 mock）。

## CHECK

- Checker从payload重新算一个s=1 gradient。
- 9N gate必须观察eligible/selected stale或若本loop只到eligibility至少有可验证s=1候选；不得mock。

## PERSIST 输出

- stale displacement
- boundary/rejection matrix
- A-STALE-01..04 evidence
- new 9N stale gate

另按 `AGENTS.md` §7 更新 PROGRESS、traceability、evidence index、checksums 与 compact handoff。

## 完成定义与停止条件

完成定义见 `AGENTS.md` §7（RED 有效、GREEN/HARDEN 通过、适用 gate 通过、Checker 允许关闭、证据/进度/handoff 持久化）。达到以下条件即停止，不为额外置信度追加运行或重构：

- boundary 矩阵 s=0/1/S_max+1/future 全部按预期、production path 对齐 oracle、9N 中 s=1 候选可验证即关闭；
- fresh anchor/选择策略留给 S4-03。

## 单一目标

用同一binary完成S_max=0/1 matched-token对照、160–410M、≥3 seeds，评估accepted-token效率和最终eval loss；形成Stage4结论/回退。

## 非目标

- 不混淆更多outer updates/通信
- 不删负面结果
- 不把9N短门禁当质量实验

## ORIENT

Codex 在修改前必须落盘：

- 当前 source spec hashes、branch/base commit 与 dirty state；
- 前置 loops 和 acceptance 是否有可复算证据；
- 当前唯一 failing gap；
- 预计修改文件与不会修改的接口；
- 本 loop 的资源、walltime、model/data/config；
- 适用时 compatible 9N baseline ID、loss/runtime阈值和fault/heterogeneity overlay；
- `miyabi-development` commit 与 host routing（涉及 Miyabi 时）。

ORIENT 结果不完整时不得进入 RED。

## SPECIFY / RED

- 实验注册表缺matched tokens/seeds/config diff时失败。
- 两臂binary commit不同或除允许轴外配置不同失败。
- eval snapshot未冻结version vector失败。

保存失败命令、exit code、fixture/config、seed、stdout/stderr。RED 必须在错误或缺失实现上确实失败。

## IMPLEMENT / GREEN

- 冻结实验矩阵、token budgets、eval protocol。
- 执行fresh/stale多种子runs；独立aggregation。
- 计算效率提升≥simulation预测50%与eval loss±1σ判定。
- 若失败默认profile回退S_max=0，机制保留。

只修当前 RED；额外重构或新策略拆成后续 loop。

## HARDEN

- seed-level raw curves、confidence/variation、accepted tokens、bytes/FLOPs/walltime。
- lambda/Qfresh/heterogeneity必要消融按计划。
- 最终commit仍跑新的8+1/50×10门禁。

低层检查未通过时不上更大拓扑。

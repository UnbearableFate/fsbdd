## 单一目标

用M=8、2≤Q<M、Q_fresh≥1、Smax=1、有限grace与异构注入运行Profile B；stale接受率>5%且与Stage0-A预测偏差≤2×。

## 非目标

- 不做最终质量结论
- 不事后调异构直到好看
- 不取消fresh-only对照

## ORIENT

Codex 在修改前必须落盘：

- 当前 source spec hashes、branch/base commit 与 dirty state；
- 前置 loops 和 acceptance 是否有可复算证据；
- 当前唯一 failing gap；
- 预计修改文件与不会修改的接口；
- 本 loop 的资源、walltime、model/data/config；
- 适用时 compatible 9N baseline ID、loss/runtime阈值和fault/heterogeneity overlay；
- `miyabi-development` commit 与 host routing（涉及 Miyabi 时）。

ORIENT 结果不完整时不得进入 RED。

## SPECIFY / RED

- 提交前根据Stage0预测冻结速度/latency profile与expected range。
- 若无真实stale selected、acceptance≤5%或偏差>2×，gate RED。
- 缺fresh/stale/rejection/weight mass metrics时report checker失败。

保存失败命令、exit code、fixture/config、seed、stdout/stderr。RED 必须在错误或缺失实现上确实失败。

## IMPLEMENT / GREEN

- 完善Profile B config和heterogeneity injection。
- 运行fresh-only同配置参考（门禁可短run）。
- 输出accepted-token efficiency、discard、update intervals、staleness distribution。

只修当前 RED；额外重构或新策略拆成后续 loop。

## HARDEN

- 至少一个repeat；检查注入实际速度比。
- visibility delay/offset未意外主导。
- 9N H=50/global10是真实主证据。

低层检查未通过时不上更大拓扑。

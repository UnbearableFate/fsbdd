## 单一目标

关闭 Stage 1：完成全部 Stage 1 acceptance 与正式 M=4/160M/真实 FS/≥1B-token
long run，并在真实 Miyabi 9 个不同计算节点上运行 8 learners+1 CPU syncer、H=50、
global_cycle=10，证明真实 Torch/HF loss 下降后建立 runtime baseline 与
CAP-BASE-TRAINING。

## 非目标

- 不以 9N 50×10 run 替代 M=4/1B-token 正式验收；两者都属于本 loop 的关闭条件
- 不启用S_max=1
- 不在9节点调试基础错误

## ORIENT

Codex 在修改前必须落盘：

- 当前 source spec hashes、branch/base commit 与 dirty state；
- 前置 loops 和 acceptance 是否有可复算证据；
- 当前唯一 failing gap；
- 预计修改文件与不会修改的接口；
- 本 loop 的资源、walltime、model/data/config；
- 适用时 compatible 9N baseline ID、loss/runtime阈值和fault/heterogeneity overlay；
- `miyabi-development` commit 与 host routing（涉及 Miyabi 时）。

ORIENT 结果不完整时不得进入 RED。

## SPECIFY / RED

- 先用synthetic role map、缺host/GPU/loss字段的假run验证topology/loss/runtime analyzer会失败。
- 1-node与2-node真实model/data smoke必须先通过。
- 门禁阈值和runtime budget在提交前冻结。

保存失败命令、exit code、fixture/config、seed、stdout/stderr。RED 必须在错误或缺失实现上确实失败。

## IMPLEMENT / GREEN

- 准备coallocated 9N launcher；应用无MPI/DDP数据面。
- Profile A或Stage1 decoupled fresh profile按冻结配置运行。
- 收集role map、config、env、loss、versions、bytes、runtime、storage snapshot。

只修当前 RED；额外重构或新策略拆成后续 loop。

## HARDEN

- 验证9 distinct hosts、8 GPU UUID、syncer CPU-only。
- loss finite、final median≤0.99 initial、slope<0；global_cycle≥10。
- active runtime预算；无queue/history增长；完整退出。
- 完成 160M、M=4、真实共享 FS、≥1B-token long run，loss 合理且证据可复算。
- 至少一次independent-jobs 8+1场景验证（可与Stage1 1B run结合）。

低层检查未通过时不上更大拓扑。

## Miyabi Final Gate

本 loop 本身即首次强制门禁：8 learners + 1 syncer，9 distinct nodes，H=50，global_cycle=10。

适用时按 `docs/06_8L1S_50X10_GATE.md` 产生新的、不可复用的 run package。队列等待不计 active runtime；所有阈值在提交前冻结。

- 确认CAP-BASE-TRAINING只在全部Stage1 acceptance/必要长跑完成后active。

Checker 使用新上下文和 `templates/CHECKER_REPORT.md`，不得仅复述 Maker 结论。

## 单一目标

关闭 Stage 1：完成全部 Stage 1 acceptance 与默认正式 M=4/160M/真实 FS/≥1B-token
long run（或 2026-07-16 用户批准的单次 early-close 例外），并在真实 Miyabi 9 个不同计算节点上运行 8 learners+1 CPU syncer、H=50、
global_cycle=10；9N workload 固定为 pretrained GPT-2 small + WikiText-2 raw packed-512，
证明真实 Torch/HF loss 下降后建立 runtime baseline 与
CAP-BASE-TRAINING。

## 非目标

- 不以 9N 50×10 run 替代 M=4/1B-token 正式验收；两者都属于本 loop 的关闭条件
- 不启用S_max=1
- 不在9节点调试基础错误

通用 ORIENT/PREFLIGHT 要求见 `AGENTS.md` §4.1、`docs/03_LOOP_ENGINEERING_PROTOCOL.md` 与 `templates/LOOP_CARD.md`，不在此重复；ORIENT 或 PREFLIGHT 不完整时不得进入 RED。本 loop 进入 RED 前必须额外冻结：

- long run 的停止条件（token/cycle 预算）、观察点与聚合公式按 X-MEASURE-01 冻结。

- 准备coallocated 9N launcher；应用无MPI/DDP数据面。
- Profile A或Stage1 decoupled fresh profile按冻结配置运行；模型/data 必须匹配

## HARDEN

- 验证9 distinct hosts、8 GPU UUID、syncer CPU-only。
- loss finite、final median≤0.99 initial、slope<0；global_cycle≥10。
- active runtime预算；无queue/history增长；完整退出。
- 完成 160M、M=4、真实共享 FS、≥1B-token long run，loss 合理且证据可复算。
- 本次用户批准例外允许以 job `2394870.opbs` 的部分观测替代上一项 completion；
  必须同时保留原 token/cycle/ratio/scheduler/package 未通过事实，且不得声称完成
  1B token。
- 至少一次independent-jobs 8+1场景验证（可与Stage1 1B run结合）。
- long run 只在短时同 profile 的 loss/runtime/storage smoke 通过后提交；首次昂贵失败
  先降级复现，不连续用 9N 或 1B-token allocation 调试。

## 完成定义与停止条件

完成定义见 `AGENTS.md` §7（RED 有效、GREEN/HARDEN 通过、适用 gate 通过、Checker 允许关闭、证据/进度/handoff 持久化）。达到以下条件即停止，不为额外置信度追加运行或重构：

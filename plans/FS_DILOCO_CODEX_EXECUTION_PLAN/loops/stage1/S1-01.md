## 单一目标

对至少两种 decoder-only naming family 建立结构化 logical-layer registry，覆盖 embedding、完整 blocks、lm_head、零散参数和 tied ownership。

## 非目标

- 不做 fragment 切分优化
- 不做 encoder-decoder/MoE
- 不依赖字符串模糊猜测

## ORIENT

Codex 在修改前必须落盘：

- 当前 source spec hashes、branch/base commit 与 dirty state；
- 前置 loops 和 acceptance 是否有可复算证据；
- 当前唯一 failing gap；
- 预计修改文件与不会修改的接口；
- 本 loop 的资源、walltime、model/data/config；
- 适用时 compatible 9N baseline ID、loss/runtime阈值和fault/heterogeneity overlay；
- `miyabi-development` commit 与 host routing（涉及 Miyabi 时）。

ORIENT 结果不完整时不得进入 RED。

## SPECIFY / RED

- 构造 Pythia/LLaMA 风格 tiny configs；naive `layers.<n>` parser 对另一 naming family 应失败。
- tied embedding/lm_head duplicate ownership fixture 必须被覆盖检查拒绝。
- 未归属 final norm/辅助 trainable param 必须失败。

保存失败命令、exit code、fixture/config、seed、stdout/stderr。RED 必须在错误或缺失实现上确实失败。

## IMPLEMENT / GREEN

- 通过 module structure/explicit adapter 识别逻辑层；不确定时要求显式 mapping。
- 输出每个 parameter identity→logical layer/owner。
- 实现零散参数相邻较小侧、平局前侧规则；记录 tied identity。

只修当前 RED；额外重构或新策略拆成后续 loop。

## HARDEN

- tied/untied、bias/no-bias、极大 embedding、零参数模块、不同顺序。
- 真实约160M HF config 仅初始化 model structure或meta device（按可行性）并生成摘要。
- 所有 trainable parameter恰好一次。

低层检查未通过时不上更大拓扑。

## Miyabi Final Gate

不适用（基础训练系统尚未完成）

适用时按 `docs/06_8L1S_50X10_GATE.md` 产生新的、不可复用的 run package。队列等待不计 active runtime；所有阈值在提交前冻结。

## CHECK

- Checker 提供第三个小 naming variation或显式 mapping case。
- 核对 forward order与逻辑层顺序。

Checker 使用新上下文和 `templates/CHECKER_REPORT.md`，不得仅复述 Maker 结论。

## PERSIST 输出

- logical-layer registry
- model adapter docs
- coverage reports for ≥2 naming families
- A-FRAG-01 evidence

另必须更新：

- `plans/PROGRESS.yaml`
- `plans/ACCEPTANCE_TRACEABILITY.csv`
- loop evidence index/checksums
- 下一最小 failing gap

- RED 在错误实现上失败；
- GREEN 与 HARDEN 全通过；
- 本 loop 相关 requirement 未被隐式改写；
- 适用时新的 9N 50×10 门禁通过；
- Checker 为 `PASS` 或允许关闭的 `PASS_WITH_FOLLOWUPS`；
- 证据、config、commit 与进度已持久化；
- 没有未登记 blocker。

## 单一目标

将new params、outer state、version、selected/consumed frontiers与policy identity作为一个逻辑整体发布；失败publication不得消费proposal。

## 非目标

- 不做完整Stage3 kill矩阵
- 不做历史event log
- 不引入global head

## ORIENT

Codex 在修改前必须落盘：

- 当前 source spec hashes、branch/base commit 与 dirty state；
- 前置 loops 和 acceptance 是否有可复算证据；
- 当前唯一 failing gap；
- 预计修改文件与不会修改的接口；
- 本 loop 的资源、walltime、model/data/config；
- 适用时 compatible 9N baseline ID、loss/runtime阈值和fault/heterogeneity overlay；
- `miyabi-development` commit 与 host routing（涉及 Miyabi 时）。

ORIENT 结果不完整时不得进入 RED。

## SPECIFY / RED

- 分别发布params和outer state的unsafe实现，在中断点读取应失败。
- 在visibility成功前写consumed frontier的实现导致retry丢proposal并失败。
- version跳号/覆盖同version不同content必须失败。

保存失败命令、exit code、fixture/config、seed、stdout/stderr。RED 必须在错误或缺失实现上确实失败。

## IMPLEMENT / GREEN

- 构造immutable global object集合与single current record。
- publication success即authority/consumption生效；失败保留旧current。
- 每fragmentversion恰好+1；old temp由GC处理。

只修当前 RED；额外重构或新策略拆成后续 loop。

## HARDEN

- 每个publication step故障注入（进程内）；duplicate retry；reader并发。
- selected set/weights固定后late proposal进下一轮。
- current record完整性/identity。

低层检查未通过时不上更大拓扑。

## Miyabi Final Gate

不适用（基础训练系统尚未完成）

适用时按 `docs/06_8L1S_50X10_GATE.md` 产生新的、不可复用的 run package。队列等待不计 active runtime；所有阈值在提交前冻结。

## CHECK

- Checker从旧current重放失败publication，确认proposal仍eligible。
- 核对无独立latest params/state。

Checker 使用新上下文和 `templates/CHECKER_REPORT.md`，不得仅复述 Maker 结论。

## PERSIST 输出

- global commit implementation
- interruption tests
- consumption traces
- A-GLOBAL/A-PROP evidence

另必须更新：

- `plans/PROGRESS.yaml`
- `plans/ACCEPTANCE_TRACEABILITY.csv`
- loop evidence index/checksums
- 下一最小 failing gap

## 完成定义

- RED 在错误实现上失败；
- GREEN 与 HARDEN 全通过；
- 本 loop 相关 requirement 未被隐式改写；
- 适用时新的 9N 50×10 门禁通过；
- Checker 为 `PASS` 或允许关闭的 `PASS_WITH_FOLLOWUPS`；
- 证据、config、commit 与进度已持久化；
- 没有未登记 blocker。

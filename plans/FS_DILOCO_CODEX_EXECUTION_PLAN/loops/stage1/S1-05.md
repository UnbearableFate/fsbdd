# S1-05：Proposal Schema、Latest-wins Discovery 与通用 Eligibility

## 元数据

| 字段 | 值 |

## 单一目标

实现每learner/fragment固定slot的proposal身份、latest monotonic、S_max参数化资格与固定大小consumed frontier；以S_max=0运行。

## 非目标

- 不生成真实snapshot
- 不执行merge
- 不硬编码base==current

## ORIENT 与 PREFLIGHT

通用 ORIENT/PREFLIGHT 要求见 `AGENTS.md` §4.1、`docs/03_LOOP_ENGINEERING_PROTOCOL.md` 与 `templates/LOOP_CARD.md`，不在此重复；ORIENT 或 PREFLIGHT 不完整时不得进入 RED。本 loop 进入 RED 前必须额外冻结：

- requirement matrix 覆盖 DISC-01/02、LEARN-07、PROP-01/03..07、STALE-01/05；
- eligibility golden vectors 直接取自 S0C-02 共享 decision vectors，不新造平行 oracle；
- latest-wins/monotonic 的权威观察点（record 内 sequence，而非文件时间）。

## SPECIFY / RED

- duplicate learner proposals不做one-per-learner时quorum错误通过。
- sequence更大但same consumed base若再次eligible必须失败。
- delayed old publication使latest倒退的unsafe implementation必须失败。
- future/missing/wrong base、tokens<=0、over-progress全部红。

## IMPLEMENT / GREEN

- 定义proposal metadata/payload record；latest only fixed slots。
- eligibility计算 `s=current-base` 与 `0<=s<=S_max`。
- 实现deterministic rejection reasons和consumed sequence/base frontiers。
- weight function统一存在但本阶段s=0。

## HARDEN

- 乱序完成、重复polling、sequence jump、same-base replacement、wrong dtype/shape/content。
- history对象数量增加不改变discovery。
- property test：同learner最多一个candidate。

## Miyabi Final Gate

不适用：CAP-BASE-TRAINING 尚未建立，首次 9N gate 在 `S1-13`。

## CHECK

- Checker用shared consumption vectors。
- 代码搜索确认无独立fresh-only path。

## PERSIST 输出

- proposal protocol
- eligibility/rejection tests
- fixed discovery benchmark
- A-PROP-01..03 evidence

另按 `AGENTS.md` §7 更新 PROGRESS、traceability、evidence index、checksums 与 compact handoff。

## 完成定义与停止条件

完成定义见 `AGENTS.md` §7（RED 有效、GREEN/HARDEN 通过、适用 gate 通过、Checker 允许关闭、证据/进度/handoff 持久化）。达到以下条件即停止，不为额外置信度追加运行或重构：

- eligibility/rejection golden vectors 与 property 全部通过、discovery 与历史体积无关即关闭；
- 不生成真实 snapshot、不执行 merge、不硬编码 base==current。

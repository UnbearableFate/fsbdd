# S1-12：Profile A 数值端到端与 Frozen Evaluation Snapshot

## 元数据

| 字段 | 值 |
|---|---|
| Stage | stage1 |
| 前置 loops | S1-07, S1-08, S1-09, S1-11 |
| 规范条款 | GLOBAL-05, PROG-01, PROG-02, PROG-03, PROG-04, REPORT-02 |
| Acceptance | A-ALG-01, A-EVAL-01, A-LEARN-01, A-LEARN-03 |
| 最高资源级别 | Miyabi 2–4 nodes |
| 9 节点门禁 | 不适用（首次 gate 在 `S1-13`） |

## 单一目标

以M小规模、Q=M、Q_fresh=M、S_max=0、grace=0跑完整闭环，对齐oracle；实现冻结version vector的evaluation snapshot。

## 非目标

- 不以此代替1B-token run
- 不做9节点baseline（下一loop）
- 不启用stale

## ORIENT 与 PREFLIGHT

通用 ORIENT/PREFLIGHT 要求见 `AGENTS.md` §4.1、`docs/03_LOOP_ENGINEERING_PROTOCOL.md` 与 `templates/LOOP_CARD.md`，不在此重复；ORIENT 或 PREFLIGHT 不完整时不得进入 RED。本 loop 进入 RED 前必须额外冻结：

- requirement matrix 覆盖 GLOBAL-05、PROG-01..04、REPORT-02；
- L2≤1e-6 与 50-update 漂移判定的对照基准：oracle 实现、dtype、聚合公式；
- M=4 最小真实 FS run 的拓扑、walltime 预算与 package profile（L2）。

## SPECIFY / RED

- 端到端single update与oracle对比先红。
- evaluation逐个追latest导致混合非冻结snapshot的并发fixture失败。
- 单learner×0.5时其他learner若等待其本地训练的timing test失败。

## IMPLEMENT / GREEN

- 整合bootstrap/learners/syncer/stop。
- evaluation先冻结vector+content identities再load。
- progress分别报告local steps、fragment counts、global_cycle。

## HARDEN

- 单次L2≤1e-6，连续50updates；mixed-version trace。
- M=4最小真实FS run；速度注入。
- byte accounting无完整模型稳态传输。

## Miyabi Final Gate

不适用：CAP-BASE-TRAINING 尚未建立，首次 9N gate 在 `S1-13`。

## CHECK

- Checker从raw proposals/current重算至少一次update。
- 核对evaluation manifest不可变。

## PERSIST 输出

- Profile A E2E harness
- numeric trace
- evaluation snapshot
- Stage1 acceptance bundle draft

另按 `AGENTS.md` §7 更新 PROGRESS、traceability、evidence index、checksums 与 compact handoff。

## 完成定义与停止条件

完成定义见 `AGENTS.md` §7（RED 有效、GREEN/HARDEN 通过、适用 gate 通过、Checker 允许关闭、证据/进度/handoff 持久化）。达到以下条件即停止，不为额外置信度追加运行或重构：

- 单 update L2≤1e-6、连续 50 updates 无漂移放大、M=4 真实 FS run 与冻结 evaluation snapshot 通过即关闭；
- 不以此替代 1B-token long run 或 9N baseline（S1-13）。

## 单一目标

以M小规模、Q=M、Q_fresh=M、S_max=0、grace=0跑完整闭环，对齐oracle；实现冻结version vector的evaluation snapshot。

## 非目标

- 不以此代替1B-token run
- 不做9节点baseline（下一loop）
- 不启用stale

## ORIENT

Codex 在修改前必须落盘：

- 当前 source spec hashes、branch/base commit 与 dirty state；
- 前置 loops 和 acceptance 是否有可复算证据；
- 当前唯一 failing gap；
- 预计修改文件与不会修改的接口；
- 本 loop 的资源、walltime、model/data/config；
- 适用时 compatible 9N baseline ID、loss/runtime阈值和fault/heterogeneity overlay；
- `miyabi-development` commit 与 host routing（涉及 Miyabi 时）。

ORIENT 结果不完整时不得进入 RED。

## SPECIFY / RED

- 端到端single update与oracle对比先红。
- evaluation逐个追latest导致混合非冻结snapshot的并发fixture失败。
- 单learner×0.5时其他learner若等待其本地训练的timing test失败。

保存失败命令、exit code、fixture/config、seed、stdout/stderr。RED 必须在错误或缺失实现上确实失败。

## IMPLEMENT / GREEN

- 整合bootstrap/learners/syncer/stop。
- evaluation先冻结vector+content identities再load。
- progress分别报告local steps、fragment counts、global_cycle。

只修当前 RED；额外重构或新策略拆成后续 loop。

## HARDEN

- 单次L2≤1e-6，连续50updates；mixed-version trace。
- M=4最小真实FS run；速度注入。
- byte accounting无完整模型稳态传输。

低层检查未通过时不上更大拓扑。

## Miyabi Final Gate

不适用（基础训练系统尚未完成）

适用时按 `docs/06_8L1S_50X10_GATE.md` 产生新的、不可复用的 run package。队列等待不计 active runtime；所有阈值在提交前冻结。

## CHECK

- Checker从raw proposals/current重算至少一次update。
- 核对evaluation manifest不可变。

Checker 使用新上下文和 `templates/CHECKER_REPORT.md`，不得仅复述 Maker 结论。

- numeric trace
- evaluation snapshot
- Stage1 acceptance bundle draft

- `plans/PROGRESS.yaml`
- `plans/ACCEPTANCE_TRACEABILITY.csv`

- 下一最小 failing gap

- 本 loop 相关 requirement 未被隐式改写；

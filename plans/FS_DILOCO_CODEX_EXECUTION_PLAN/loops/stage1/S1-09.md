## 单一目标

实现单逻辑syncer的per-fragment readiness state machine、distinct-learner quorum、固定grace与确定性无饥饿调度；S_max=0。

## 非目标

- 不做merge/commit
- 不做adaptive grace
- 不做多syncer

## ORIENT

Codex 在修改前必须落盘：

- 当前 source spec hashes、branch/base commit 与 dirty state；
- 前置 loops 和 acceptance 是否有可复算证据；
- 当前唯一 failing gap；
- 预计修改文件与不会修改的接口；
- 本 loop 的资源、walltime、model/data/config；
- 适用时 compatible 9N baseline ID、loss/runtime阈值和fault/heterogeneity overlay；
- `miyabi-development` commit 与 host routing（涉及 Miyabi 时）。

ORIENT 结果不完整时不得进入 RED。

## SPECIFY / RED

- 按文件数而非distinct learner计quorum的实现必须失败。
- CPU loop次数驱动update的实现，在无新proposal时错误ready。
- 持续高频f0导致f1饥饿的scheduler fixture失败。
- selected set受目录顺序/后到proposal改变时失败。

保存失败命令、exit code、fixture/config、seed、stdout/stderr。RED 必须在错误或缺失实现上确实失败。

## IMPLEMENT / GREEN

- 固定current version并读取eligible candidates；Q/Q_fresh readiness。
- grace start/end明确；grace后freeze selected set。
- round-robin或确定性age-based无饥饿调度。

只修当前 RED；额外重构或新策略拆成后续 loop。

## HARDEN

- multiple fragments ready、late arrival、duplicate slots、quorum loss/recovery。
- clock/tie deterministic；restart可从authority重建 readiness。
- polling history独立。

低层检查未通过时不上更大拓扑。

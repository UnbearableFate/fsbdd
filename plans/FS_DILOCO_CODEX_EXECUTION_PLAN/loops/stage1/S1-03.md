## 单一目标

实现仅依赖原子 visibility record 替换与最终可读的 storage interface，以及 immutable payload-first/visibility-last POSIX backend。

## 非目标

- 不实现 proposal/global业务语义
- 不依赖锁/append/目录事务
- 不做对象存储backend

## ORIENT

Codex 在修改前必须落盘：

- 当前 source spec hashes、branch/base commit 与 dirty state；
- 前置 loops 和 acceptance 是否有可复算证据；
- 当前唯一 failing gap；
- 预计修改文件与不会修改的接口；
- 本 loop 的资源、walltime、model/data/config；
- 适用时 compatible 9N baseline ID、loss/runtime阈值和fault/heterogeneity overlay；
- `miyabi-development` commit 与 host routing（涉及 Miyabi 时）。

ORIENT 结果不完整时不得进入 RED。

## SPECIFY / RED

- unsafe direct-overwrite writer在并发 reader test中必须出现 partial/invalid并失败。
- reader尝试扫描payload目录发现最新对象的实现必须被接口 test拒绝。
- checksum/size/schema/base identity任一不匹配必须拒绝。

保存失败命令、exit code、fixture/config、seed、stdout/stderr。RED 必须在错误或缺失实现上确实失败。

## IMPLEMENT / GREEN

- write unique temp/immutable final payload，校验后原子替换小record。
- reader只follow visibility record并验证完整性。
- 实现可注入visibility delay的hook接口（真正perf在Stage2）。

只修当前 RED；额外重构或新策略拆成后续 loop。

## HARDEN

- writer crash before/after payload、before/after record rename；multiple readers。
- record corruption、payload truncation、wrong identity。
- fixed-slot API不暴露history scan。

低层检查未通过时不上更大拓扑。

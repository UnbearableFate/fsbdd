## 单一目标

建立可安装的 Python 项目、角色 CLI 骨架、typed configuration、identity/digest、structured logging 与证据目录，使后续实现无法绕过冻结配置。

## 非目标

- 不加载真实大模型
- 不实现 storage protocol
- 不跑9节点

## ORIENT

Codex 在修改前必须落盘：

- 当前 source spec hashes、branch/base commit 与 dirty state；
- 前置 loops 和 acceptance 是否有可复算证据；
- 当前唯一 failing gap；
- 预计修改文件与不会修改的接口；
- 本 loop 的资源、walltime、model/data/config；
- 适用时 compatible 9N baseline ID、loss/runtime阈值和fault/heterogeneity overlay；
- `miyabi-development` commit 与 host routing（涉及 Miyabi 时）。

ORIENT 结果不完整时不得进入 RED。

## SPECIFY / RED

- schema tests：缺 S_max/Q/Q_fresh/H/offset/model/data/storage/stop/seed 字段时失败。
- identity tests：任一 model/fragment/config 字段变化必须改变 digest；canonical ordering 不应改变 digest。
- manifest checker：dirty commit、source hash/skill commit缺失时标记不可作为正式 run。

保存失败命令、exit code、fixture/config、seed、stdout/stderr。RED 必须在错误或缺失实现上确实失败。

## IMPLEMENT / GREEN

- 创建 pyproject/uv lock 策略、package/CLI skeleton、config dataclasses或schema。
- 实现 resolved config freeze、run_id、SHA-256 digests、UTC/monotonic structured logger。
- 提供 bootstrap/learner/syncer/checker 入口的 dry-run 参数解析。

只修当前 RED；额外重构或新策略拆成后续 loop。

## HARDEN

- unknown field、schema version mismatch、环境变量 override 冲突、路径权限。
- 静态运行不导入 torch/HF重型模块；lazy imports。
- 在 Miyabi login 节点只做静态解析/bash-n。

低层检查未通过时不上更大拓扑。

## Miyabi Final Gate

不适用（基础训练系统尚未完成）

适用时按 `docs/06_8L1S_50X10_GATE.md` 产生新的、不可复用的 run package。队列等待不计 active runtime；所有阈值在提交前冻结。

## CHECK

- Checker 变更 config 字段并重算 digest。
- 确认算法字段无隐式环境变量默认。

Checker 使用新上下文和 `templates/CHECKER_REPORT.md`，不得仅复述 Maker 结论。

## PERSIST 输出

- project skeleton
- config schema and examples
- manifest schema
- structured logging schema
- traceability update

另必须更新：

- `plans/PROGRESS.yaml`
- `plans/ACCEPTANCE_TRACEABILITY.csv`
- loop evidence index/checksums
- 下一最小 failing gap

## 完成定义

- RED 在错误实现上失败；
- GREEN 与 HARDEN 全通过；
- 本 loop 相关 requirement 未被隐式改写；
- 适用时新的 9N 50×10 门禁通过；
- Checker 为 `PASS` 或允许关闭的 `PASS_WITH_FOLLOWUPS`；
- 证据、config、commit 与进度已持久化；
- 没有未登记 blocker。

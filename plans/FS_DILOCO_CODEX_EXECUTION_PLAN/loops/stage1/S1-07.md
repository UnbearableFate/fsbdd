# S1-07：H/Offset Fragment Snapshot 与 Proposal Publish

## 元数据

| 字段 | 值 |
|---|---|
| Stage | stage1 |
| 前置 loops | S1-05, S1-06, S1-02 |
| 规范条款 | LEARN-03, LEARN-04, LEARN-05, LEARN-06, LEARN-07, LEARN-11, PROG-06 |
| Acceptance | 本 loop 为后续 acceptance 提供组成证据 |
| 最高资源级别 | Miyabi 1–2 nodes |
| 9 节点门禁 | 不适用（首次 gate 在 `S1-13`） |

## 单一目标

在完整inner step后按H/offset生成目标fragment不可变snapshot，携带真实base identity/tokens/steps并发布到latest slot；训练不等syncer。

## 非目标

- Stage2前不要求完全异步重叠
- 不同时snapshot完整模型
- 不在in-flight时改写base

## ORIENT 与 PREFLIGHT

通用 ORIENT/PREFLIGHT 要求见 `AGENTS.md` §4.1、`docs/03_LOOP_ENGINEERING_PROTOCOL.md` 与 `templates/LOOP_CARD.md`，不在此重复；ORIENT 或 PREFLIGHT 不完整时不得进入 RED。本 loop 进入 RED 前必须额外冻结：

- requirement matrix 覆盖 LEARN-03..07/11、PROG-06；
- snapshot 时序权威观察点：safe-boundary 事件、in-flight 判定与 pending 上限；
- 2-node writer/reader run 沿用 S1-00 package validator（L2 profile）。

## SPECIFY / RED

- 在optimizer mutation中取snapshot的fixture应捕获不一致。
- 到期scheduler若同一步突发所有fragments，offset test失败。
- in-flight proposal后adopt新base时，proposal metadata被改写的实现失败。

## IMPLEMENT / GREEN

- 实现deterministic offset scheduler和per-fragment due判断。
- 提取目标fragment state；proposal sequence单调。
- 初版bounded pending/in-flight机制；S1可允许有限同步写但不得等待其他learner/quorum。

## HARDEN

- skip/replacement、slow writer、fragment bytes不均、restart sequence预留。
- byte accounting确保payload仅目标fragment。
- 2-node writer/reader真实FS。

## Miyabi Final Gate

不适用：CAP-BASE-TRAINING 尚未建立，首次 9N gate 在 `S1-13`。

## CHECK

- Checker追踪一个snapshot的parameter/base/tokens/safe-step identity。
- 确认learner主循环不等待syncer。

## PERSIST 输出

- snapshot scheduler
- proposal publisher
- timing/byte traces
- RED concurrency fixtures

另按 `AGENTS.md` §7 更新 PROGRESS、traceability、evidence index、checksums 与 compact handoff。

## 完成定义与停止条件

完成定义见 `AGENTS.md` §7（RED 有效、GREEN/HARDEN 通过、适用 gate 通过、Checker 允许关闭、证据/进度/handoff 持久化）。达到以下条件即停止，不为额外置信度追加运行或重构：

- snapshot 一致性/offset 分散/in-flight metadata 不可变反例关闭、2-node 真实 FS 通过即关闭；
- 不追求完全异步重叠（Stage 2），不同时 snapshot 完整模型。

## 单一目标

在完整inner step后按H/offset生成目标fragment不可变snapshot，携带真实base identity/tokens/steps并发布到latest slot；训练不等syncer。

## 非目标

- Stage2前不要求完全异步重叠
- 不同时snapshot完整模型
- 不在in-flight时改写base

## ORIENT

Codex 在修改前必须落盘：

- 当前 source spec hashes、branch/base commit 与 dirty state；
- 前置 loops 和 acceptance 是否有可复算证据；
- 当前唯一 failing gap；
- 预计修改文件与不会修改的接口；
- 本 loop 的资源、walltime、model/data/config；
- 适用时 compatible 9N baseline ID、loss/runtime阈值和fault/heterogeneity overlay；
- `miyabi-development` commit 与 host routing（涉及 Miyabi 时）。

ORIENT 结果不完整时不得进入 RED。

## SPECIFY / RED

- 在optimizer mutation中取snapshot的fixture应捕获不一致。
- 到期scheduler若同一步突发所有fragments，offset test失败。
- in-flight proposal后adopt新base时，proposal metadata被改写的实现失败。

保存失败命令、exit code、fixture/config、seed、stdout/stderr。RED 必须在错误或缺失实现上确实失败。

## IMPLEMENT / GREEN

- 实现deterministic offset scheduler和per-fragment due判断。
- 提取目标fragment state；proposal sequence单调。
- 初版bounded pending/in-flight机制；S1可允许有限同步写但不得等待其他learner/quorum。

只修当前 RED；额外重构或新策略拆成后续 loop。

## HARDEN

- skip/replacement、slow writer、fragment bytes不均、restart sequence预留。
- byte accounting确保payload仅目标fragment。
- 2-node writer/reader真实FS。

低层检查未通过时不上更大拓扑。

## Miyabi Final Gate

不适用（基础训练系统尚未完成）

适用时按 `docs/06_8L1S_50X10_GATE.md` 产生新的、不可复用的 run package。队列等待不计 active runtime；所有阈值在提交前冻结。

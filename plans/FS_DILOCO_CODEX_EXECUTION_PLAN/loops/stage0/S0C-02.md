## 单一目标

补齐 one-per-learner、consumed sequence/base 与 direct averaging/Nesterov 的最小状态迁移，并建立初版 requirement-to-evidence map。

## 非目标

- 不实现持久化存储
- 不实现生产 outer optimizer kernel
- 不跑训练

## ORIENT

Codex 在修改前必须落盘：

- 当前 source spec hashes、branch/base commit 与 dirty state；
- 前置 loops 和 acceptance 是否有可复算证据；
- 当前唯一 failing gap；
- 预计修改文件与不会修改的接口；
- 本 loop 的资源、walltime、model/data/config；
- 适用时 compatible 9N baseline ID、loss/runtime阈值和fault/heterogeneity overlay；
- `miyabi-development` commit 与 host routing（涉及 Miyabi 时）。

ORIENT 结果不完整时不得进入 RED。

## SPECIFY / RED

- 构造同 learner 两个 proposal、same-base 更新 sequence、重复 polling、不同 base 的决策表；缺少消费规则时必须重复计票并失败。
- 构造 momentum/Nesterov 两步 transition，错误更新顺序或状态复用必须失败。
- 先建立有缺口的 traceability checker，证明未映射 requirement 会使检查失败。

保存失败命令、exit code、fixture/config、seed、stdout/stderr。RED 必须在错误或缺失实现上确实失败。

## IMPLEMENT / GREEN

- 扩展 oracle package，输出 selected set、consumed frontier、new params/state 的 reference。
- 建立 shared decision-vector 文件，供 Stage 0-A simulator 与 Stage 1 protocol tests 使用。
- 生成条款 ID→fixture/test 的初版 CSV。

只修当前 RED；额外重构或新策略拆成后续 loop。

## HARDEN

- 目录顺序乱序、sequence 跳号、same-base replacement、空 candidate、one contributor。
- outer lr=1/no momentum 与 direct averaging 等价控制。

低层检查未通过时不上更大拓扑。

## Miyabi Final Gate

不适用（基础训练系统尚未完成）

适用时按 `docs/06_8L1S_50X10_GATE.md` 产生新的、不可复用的 run package。队列等待不计 active runtime；所有阈值在提交前冻结。

## CHECK

- Checker 用不同 proposal 顺序重放并确认确定性。
- 确认 consumed frontier 只有成功 publication 后才生效的语义在 reference 中显式。

Checker 使用新上下文和 `templates/CHECKER_REPORT.md`，不得仅复述 Maker 结论。

## PERSIST 输出

- consumption decision vectors
- outer optimizer golden transitions
- initial requirement/evidence map
- Checker report

另必须更新：

- `plans/PROGRESS.yaml`
- `plans/ACCEPTANCE_TRACEABILITY.csv`
- loop evidence index/checksums
- 下一最小 failing gap

## 完成定义

- RED 在错误实现上失败；
- GREEN 与 HARDEN 全通过；
- 本 loop 相关 requirement 未被隐式改写；
- 适用时新的 9N 50×10 门禁通过；
- Checker 为 `PASS` 或允许关闭的 `PASS_WITH_FOLLOWUPS`；
- 证据、config、commit 与进度已持久化；
- 没有未登记 blocker。

# S0B-02：跨节点可见性与 10^5 次原子发布验证

## 元数据

| 字段 | 值 |
|---|---|
| Stage | stage0 |
| 前置 loops | S0B-01 |
| 规范条款 | BENCH-01, BENCH-02, STOR-01, FS-02 |
| Acceptance | A-BENCH-01, A-BENCH-02 |
| 最高资源级别 | Miyabi ≥2 compute nodes |
| 9 节点门禁 | 不适用（基础训练系统尚未完成） |

## 单一目标

测量空载/负载跨节点 publication→readable p50/p99，并在并发 reader/writer 下完成至少 10^5 次 visibility record 原子替换、0 半提交。

## 非目标

- 不测大带宽/metadata full matrix
- 不以单节点 rename 代替跨节点

## ORIENT

Codex 在修改前必须落盘：

- 当前 source spec hashes、branch/base commit 与 dirty state；
- 前置 loops 和 acceptance 是否有可复算证据；
- 当前唯一 failing gap；
- 预计修改文件与不会修改的接口；
- 本 loop 的资源、walltime、model/data/config；
- 适用时 compatible 9N baseline ID、loss/runtime阈值和fault/heterogeneity overlay；
- `miyabi-development` commit 与 host routing（涉及 Miyabi 时）。

ORIENT 结果不完整时不得进入 RED。

## SPECIFY / RED

- 先实现 reader 的 partial/torn record detector；故意使用直接覆盖 record 的 unsafe writer，应观察失败。
- 计时起点/终点定义 test；错误把 payload write start 当 publication complete 必须被 schema checker 拒绝。
- 负载 profile 缺失时 acceptance checker 失败。

保存失败命令、exit code、fixture/config、seed、stdout/stderr。RED 必须在错误或缺失实现上确实失败。

## IMPLEMENT / GREEN

- 实现 payload-first、small-record visibility-last benchmark。
- 记录每次 sequence/content checksum、publish/read timestamps、retry/poll count。
- 空载与背景负载两组；≥10^5 atomic replacements。

只修当前 RED；额外重构或新策略拆成后续 loop。

## HARDEN

- 多 reader、record 尺寸变化、writer kill 前后、cache-warm/cold。
- 统计 p50/p95/p99/max 与 violation count。
- 确认 clock 使用单节点 elapsed 或明确消除跨节点 clock skew。

低层检查未通过时不上更大拓扑。

## Miyabi Final Gate

不适用（基础训练系统尚未完成）

适用时按 `docs/06_8L1S_50X10_GATE.md` 产生新的、不可复用的 run package。队列等待不计 active runtime；所有阈值在提交前冻结。

## CHECK

- Checker 检查原始 violation scanner，而非只看汇总。
- 按阈值 `p99 <= min(5s, 5%H)` 判定。

Checker 使用新上下文和 `templates/CHECKER_REPORT.md`，不得仅复述 Maker 结论。

## PERSIST 输出

- raw latency/atomicity logs
- summary report
- unsafe-writer RED evidence
- A-BENCH-01/02 verdict

另必须更新：

- `plans/PROGRESS.yaml`
- `plans/ACCEPTANCE_TRACEABILITY.csv`
- loop evidence index/checksums
- 下一最小 failing gap

## 完成定义

- RED 在错误实现上失败；
- GREEN 与 HARDEN 全通过；
- 本 loop 相关 requirement 未被隐式改写；
- 适用时新的 9N 50×10 门禁通过；
- Checker 为 `PASS` 或允许关闭的 `PASS_WITH_FOLLOWUPS`；
- 证据、config、commit 与进度已持久化；
- 没有未登记 blocker。

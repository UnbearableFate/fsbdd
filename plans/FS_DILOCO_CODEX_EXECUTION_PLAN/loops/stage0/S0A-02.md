# S0A-02：参数扫描、默认 Profile 与 stale 挽回预测

## 元数据

| 字段 | 值 |
|---|---|
| Stage | stage0 |
| 前置 loops | S0A-01 |
| 规范条款 | SIM-03, SIM-04, SIM-05 |
| Acceptance | A-SIM-02, A-SIM-03 |
| 最高资源级别 | CPU batch/local |
| 9 节点门禁 | 不适用（基础训练系统尚未完成） |

## 单一目标

覆盖规定扫描矩阵，产出 discard/accepted-token/update interval/stale acceptance，并冻结 Stage 1/4 默认参数建议与 Stage 5 延迟测点建议。

## 非目标

- 不以预测取消 Stage 4
- 不宣称训练质量
- 不事后挑选只支持假设的点

## ORIENT

Codex 在修改前必须落盘：

- 当前 source spec hashes、branch/base commit 与 dirty state；
- 前置 loops 和 acceptance 是否有可复算证据；
- 当前唯一 failing gap；
- 预计修改文件与不会修改的接口；
- 本 loop 的资源、walltime、model/data/config；
- 适用时 compatible 9N baseline ID、loss/runtime阈值和fault/heterogeneity overlay；
- `miyabi-development` commit 与 host routing（涉及 Miyabi 时）。

ORIENT 结果不完整时不得进入 RED。

## SPECIFY / RED

- 写矩阵完整性 test：缺任一 M/Q/heterogeneity/grace/visibility 组合即失败。
- 写 report schema checker：缺 discard、accepted tokens、interval、recovery prediction 即失败。
- 构造 known symmetric case，期望 fresh-only 接受率/interval 的解析 sanity。

保存失败命令、exit code、fixture/config、seed、stdout/stderr。RED 必须在错误或缺失实现上确实失败。

## IMPLEMENT / GREEN

- 实现可并行、可恢复的 sweep runner；每点记录 config/seed/version。
- 输出原始 parquet/CSV、聚合表、默认建议和不确定性。
- 明确 stale recovery ≥10、3–10、<3 percentage points 的论文篇幅分类。

只修当前 RED；额外重构或新策略拆成后续 loop。

## HARDEN

- 至少重复关键默认点；检查 seed sensitivity。
- 检查单位与 token-weighted 口径。
- 报告 visibility delay/H 比值，而非只报告秒。

低层检查未通过时不上更大拓扑。

## Miyabi Final Gate

不适用（基础训练系统尚未完成）

适用时按 `docs/06_8L1S_50X10_GATE.md` 产生新的、不可复用的 run package。队列等待不计 active runtime；所有阈值在提交前冻结。

## CHECK

- Checker 随机抽查矩阵组合并重算。
- 确认预测只作为参数/验收锚点，不进入 correctness。

Checker 使用新上下文和 `templates/CHECKER_REPORT.md`，不得仅复述 Maker 结论。

## PERSIST 输出

- full sweep manifest
- raw/aggregated results
- default profile recommendation
- Stage 4 prediction anchor
- Stage 5 delay point recommendation

另必须更新：

- `plans/PROGRESS.yaml`
- `plans/ACCEPTANCE_TRACEABILITY.csv`
- loop evidence index/checksums
- 下一最小 failing gap

## 完成定义

- RED 在错误实现上失败；
- GREEN 与 HARDEN 全通过；
- 本 loop 相关 requirement 未被隐式改写；
- 适用时新的 9N 50×10 门禁通过；
- Checker 为 `PASS` 或允许关闭的 `PASS_WITH_FOLLOWUPS`；
- 证据、config、commit 与进度已持久化；
- 没有未登记 blocker。

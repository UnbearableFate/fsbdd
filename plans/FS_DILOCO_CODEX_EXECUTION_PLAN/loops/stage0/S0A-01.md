## 单一目标

实现 M learners/F fragments 的 deterministic event simulator，忠实模拟 H/offset、速度、upload/visibility、Q/grace、S_max、one-per-learner 和 same-base consumption。

## 非目标

- 不模拟 loss/质量
- 不复制生产 storage 代码
- 不做完整参数扫描

## ORIENT

Codex 在修改前必须落盘：

- 当前 source spec hashes、branch/base commit 与 dirty state；
- 前置 loops 和 acceptance 是否有可复算证据；
- 当前唯一 failing gap；
- 预计修改文件与不会修改的接口；
- 本 loop 的资源、walltime、model/data/config；
- 适用时 compatible 9N baseline ID、loss/runtime阈值和fault/heterogeneity overlay；
- `miyabi-development` commit 与 host routing（涉及 Miyabi 时）。

ORIENT 结果不完整时不得进入 RED。

## SPECIFY / RED

- 让 simulator 先读取 S0C shared decision vectors；空实现或 naive latest-counting 对 duplicate/same-base fixture 必须失败。
- 构造 visibility delay 导致 fresh→stale 的事件序列。
- 构造超过候选上限时排序不同导致非确定结果的反例。

保存失败命令、exit code、fixture/config、seed、stdout/stderr。RED 必须在错误或缺失实现上确实失败。

## IMPLEMENT / GREEN

- 用显式 event queue 和稳定 tie-break 实现。
- 事件与状态 schema 可序列化；随机性完全由 seed 控制。
- 接受/拒绝原因与生产计划中的分类一致。

只修当前 RED；额外重构或新策略拆成后续 loop。

## HARDEN

- constant speed 与 lognormal jitter；M=1小边界仅供测试、M=4真实 profile。
- 重复 seed bitwise/record-equivalent；不同目录/插入顺序结果一致。
- 检查 state/history 不随模拟更新无界增长。

低层检查未通过时不上更大拓扑。

## Miyabi Final Gate

不适用（基础训练系统尚未完成）

适用时按 `docs/06_8L1S_50X10_GATE.md` 产生新的、不可复用的 run package。队列等待不计 active runtime；所有阈值在提交前冻结。

## CHECK

- Checker 对照 shared vectors，并手工重放至少一条 grace-window timeline。
- 核对 simulator 不被 runtime 使用。

Checker 使用新上下文和 `templates/CHECKER_REPORT.md`，不得仅复述 Maker 结论。

## PERSIST 输出

- simulator core
- shared-vector conformance report
- event trace sample
- seed/reproducibility evidence

另必须更新：

- `plans/PROGRESS.yaml`
- `plans/ACCEPTANCE_TRACEABILITY.csv`
- loop evidence index/checksums
- 下一最小 failing gap

## 完成定义

- RED 在错误实现上失败；
- GREEN 与 HARDEN 全通过；
- 本 loop 相关 requirement 未被隐式改写；
- 适用时新的 9N 50×10 门禁通过；
- Checker 为 `PASS` 或允许关闭的 `PASS_WITH_FOLLOWUPS`；
- 证据、config、commit 与进度已持久化；
- 没有未登记 blocker。

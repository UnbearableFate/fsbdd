## 单一目标

使用 miyabi-development 安全进入 Miyabi compute nodes，确认真实 target RUN_ROOT、PBS/模块/路径，并建立可重复的跨节点 storage benchmark harness。

## 非目标

- 不在 login 节点运行 benchmark
- 不先得出 FS 合格结论
- 不硬编码 skill 示例常量

## ORIENT

Codex 在修改前必须落盘：

- 当前 source spec hashes、branch/base commit 与 dirty state；
- 前置 loops 和 acceptance 是否有可复算证据；
- 当前唯一 failing gap；
- 预计修改文件与不会修改的接口；
- 本 loop 的资源、walltime、model/data/config；
- 适用时 compatible 9N baseline ID、loss/runtime阈值和fault/heterogeneity overlay；
- `miyabi-development` commit 与 host routing（涉及 Miyabi 时）。

ORIENT 结果不完整时不得进入 RED。

## SPECIFY / RED

- 静态 checker 要求 manifest 含 skill commit、hostname/PBS/nodefile、RUN_ROOT、fs identity、module list；缺字段失败。
- 2-node dry harness 在错误的 node-local path 上必须检测到跨节点不可见并拒绝。
- benchmark 命令若在 login host 分类下运行必须 fail fast。

保存失败命令、exit code、fixture/config、seed、stdout/stderr。RED 必须在错误或缺失实现上确实失败。

## IMPLEMENT / GREEN

- 安装/读取 miyabi-development；记录 commit。
- 实现 writer/reader role launcher、fixed payload generator、monotonic timing、structured output。
- 探测 target FS mount/device/quota/permissions，区分 shared protocol path 与 local staging。

只修当前 RED；额外重构或新策略拆成后续 loop。

## HARDEN

- 1-node static/format、2-node tiny visibility smoke。
- PBS script `bash -n`；roles 记录 distinct hosts。
- 重复运行不覆盖旧证据。

低层检查未通过时不上更大拓扑。

## Miyabi Final Gate

不适用（基础训练系统尚未完成）

适用时按 `docs/06_8L1S_50X10_GATE.md` 产生新的、不可复用的 run package。队列等待不计 active runtime；所有阈值在提交前冻结。

## CHECK

- Checker 核对运行发生在 PBS compute nodes。
- 核对被测路径确是后续 protocol RUN_ROOT。

Checker 使用新上下文和 `templates/CHECKER_REPORT.md`，不得仅复述 Maker 结论。

## PERSIST 输出

- Miyabi environment manifest
- benchmark harness
- 2-node smoke evidence
- target FS decision record draft

另必须更新：

- `plans/PROGRESS.yaml`
- `plans/ACCEPTANCE_TRACEABILITY.csv`

- 下一最小 failing gap

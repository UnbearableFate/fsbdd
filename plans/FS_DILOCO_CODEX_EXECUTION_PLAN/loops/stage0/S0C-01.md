## 单一目标

建立不依赖生产实现的标量/小向量 reference math，明确 fresh 与 s=1 stale 的 base-relative pseudo-gradient，并提供错误公式的必失败反例。

## 非目标

- 不实现 syncer/learner
- 不做性能优化
- 不决定 stale 是否实现

## ORIENT

Codex 在修改前必须落盘：

- 当前 source spec hashes、branch/base commit 与 dirty state；
- 前置 loops 和 acceptance 是否有可复算证据；
- 当前唯一 failing gap；
- 预计修改文件与不会修改的接口；
- 本 loop 的资源、walltime、model/data/config；
- 适用时 compatible 9N baseline ID、loss/runtime阈值和fault/heterogeneity overlay；
- `miyabi-development` commit 与 host routing（涉及 Miyabi 时）。

ORIENT 结果不完整时不得进入 RED。

## SPECIFY / RED

- 先写 `G_current - L_stale` 的错误替身，使用 current 与 old base 不同的向量，证明结果与 reference 不同且测试失败。
- 写 fresh 标量、fresh 向量、stale s=1、不同 tokens/lambda 的 golden fixtures。
- 写 weights 非负、归一化、fresh 无折扣、staleness 单调不增的 property tests。

保存失败命令、exit code、fixture/config、seed、stdout/stderr。RED 必须在错误或缺失实现上确实失败。

## IMPLEMENT / GREEN

- 实现纯函数 reference oracle；禁止导入生产 syncer/storage 代码。
- 输出 canonical fixtures（JSON/YAML + expected tensors）供 simulator 和运行时测试复用。
- 固定 fp32 累加与容差。

只修当前 RED；额外重构或新策略拆成后续 loop。

## HARDEN

- 随机小向量 property test；lambda=0、tokens 极不均衡、单 contributor、mixed fresh/stale。
- 验证错误替身、wrong base identity 和 future base fixture 都被拒绝。

低层检查未通过时不上更大拓扑。

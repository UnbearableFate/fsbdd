# S0B-03：Metadata/Bandwidth 压测与 Stage 1 FS 决策

## 元数据

| 字段 | 值 |
|---|---|
| Stage | stage0 |
| 前置 loops | S0B-02 |
| 规范条款 | BENCH-03, BENCH-04, FS-05, FS-06, BENCH-05 |
| Acceptance | A-BENCH-03, A-BENCH-04 |
| 最高资源级别 | Miyabi 2–16 compute nodes |
| 9 节点门禁 | 不适用（基础训练系统尚未完成） |

## 单一目标

模拟 M×F fixed-slot polling，测 metadata throughput/latency 与 50–500MB single/M-concurrent sequential I/O，并形成通过或缓解决策。

## 非目标

- 不实现生产 GC
- 不把另一个 FS 的结果冒充 target FS
- 不掩盖 quota/MDT 影响

## ORIENT

Codex 在修改前必须落盘：

- 当前 source spec hashes、branch/base commit 与 dirty state；
- 前置 loops 和 acceptance 是否有可复算证据；
- 当前唯一 failing gap；
- 预计修改文件与不会修改的接口；
- 本 loop 的资源、walltime、model/data/config；
- 适用时 compatible 9N baseline ID、loss/runtime阈值和fault/heterogeneity overlay；
- `miyabi-development` commit 与 host routing（涉及 Miyabi 时）。

ORIENT 结果不完整时不得进入 RED。

## SPECIFY / RED

- 矩阵完整性 checker：payload sizes、single/M-concurrent、M×F polling 缺点即失败。
- 错误 history-scanning benchmark 应显示成本随 history 增长并被 bounded-discovery checker 拒绝。
- 阈值 report 缺稳态需求计算即失败。

保存失败命令、exit code、fixture/config、seed、stdout/stderr。RED 必须在错误或缺失实现上确实失败。

## IMPLEMENT / GREEN

- 实现 fixed-slot stat/read/readdir profiles和 payload write/read。
- 报告 metadata ops/s、latency、MDS影响代理、aggregate/per-stream bandwidth。
- 计算 M=16/F=32/1s polling需求与 10×裕量；计算一轮 fragments time/H。

只修当前 RED；额外重构或新策略拆成后续 loop。

## HARDEN

- 不同并发度、cold/warm、目录布局；临时对象数量。
- 重复关键点，报告变异。
- 检查 benchmark 本身不造成历史目录增长。

低层检查未通过时不上更大拓扑。

## Miyabi Final Gate

不适用（基础训练系统尚未完成）

适用时按 `docs/06_8L1S_50X10_GATE.md` 产生新的、不可复用的 run package。队列等待不计 active runtime；所有阈值在提交前冻结。

## CHECK

- Checker 重算 A-BENCH-03/04。
- 不达标时验证 mitigation（换 path、增大H、显式 barrier）并冻结 Stage1 profile。

Checker 使用新上下文和 `templates/CHECKER_REPORT.md`，不得仅复述 Maker 结论。

## PERSIST 输出

- metadata/bandwidth raw data
- threshold calculation
- FS PASS or mitigation ADR
- Stage 0 checkpoint input

另必须更新：

- `plans/PROGRESS.yaml`
- `plans/ACCEPTANCE_TRACEABILITY.csv`
- loop evidence index/checksums
- 下一最小 failing gap

## 完成定义

- RED 在错误实现上失败；
- GREEN 与 HARDEN 全通过；
- 本 loop 相关 requirement 未被隐式改写；
- 适用时新的 9N 50×10 门禁通过；
- Checker 为 `PASS` 或允许关闭的 `PASS_WITH_FOLLOWUPS`；
- 证据、config、commit 与进度已持久化；
- 没有未登记 blocker。

# 06. Miyabi 8 Learner + 1 Syncer、50×10 门禁

## 6.1 适用范围

- `S1-13`：首次执行，建立 `BASELINE-9N-GPT2-WT2-v1`；
- Stage 2–4 的每个实现 loop：必须执行一次新的 run，或由其预注册 gate 单元
  （`AGENTS.md` §5.1；当前 `GU-S2-ASYNC`、`GU-S3-CRASH`、`GU-S4-STALE-SELECT`）
  的单元 run 一并履行——单元 run 的 analyzer 必须同时断言单元内每个 loop 的
  overlay 判据，失败且根因涉及先行 loop 时两个 loop 一并重开；
- 一次 run 可在提交前预注册为双重用途（loop gate + stage-level experiment，如
  S2-03 的 slow-FS 2h run），overlay 必须同时满足两者判据；
- 仅文档拼写类改动不形成实现 loop；任何运行代码、配置 schema、依赖、PBS、测试 fixture、model/data 或默认值变化都触发门禁。

## 6.2 拓扑硬条件

门禁 PASS 必须同时满足：

| 条件 | 证明 |
|---|---|
| 8 learners | role manifest + 8 个 learner logs |
| 1 syncer | syncer log；无第二可写 syncer |
| 9 distinct compute hosts | `$PBS_NODEFILE`、每角色 `hostname`、去重检查 |
| 每 learner 1 GPU | `CUDA_VISIBLE_DEVICES`、torch device、GPU UUID/型号 |
| syncer CPU-only | `CUDA_VISIBLE_DEVICES` 空/禁用，代码不初始化 CUDA |
| shared protocol FS | 所有角色记录同一 RUN_ROOT/device/fs identity |
| no network data plane | config、代码检查、无 distributed process group/RPC |

coallocated 模式允许 MPI/PBS 启动进程；MPI 不得用于 payload/coordination。

## 6.3 训练条件

```yaml
learners: 8
syncers: 1
local_optimizer_step_interval_H: 50
target_global_cycles: 10
model: openai-community/gpt2@607a30d783dfa663caf39e06633721c8d4cfcd7e
data: Salesforce/wikitext@b08601e04326c79dfdd32d625aee71d232d685c3 / wikitext-2-raw-v1
inner_optimizer: AdamW-like
outer_merge: loop/profile specified
outer_optimizer: fragment-wise SGD momentum/Nesterov
```

`H=50` 是 per-fragment 计划间隔。`target_global_cycles=10` 表示每个 fragment outer count 至少 10。实际 local steps/tokens 和 fragment update counts全部报告。

`F`、offsets、`Q/Q_fresh`、`S_max/lambda_s`、grace 和 outer optimizer 不在本文件中
猜测：`S1-13` 合并 Stage 0 已冻结的 Profile A，后续 loop 合并各自 frozen overlay。resolved
config 中这些字段必须全部非 null；offset 数量等于 `F`、每项为 `[0,49]` 整数，并通过按
fragment bytes 加权的 burst 检查。未解析字段或运行中修改均为 `EVIDENCE_FAIL`。

### 6.3.1 GPT-2 模型冻结

9 节点回归 profile 固定为 Hugging Face `openai-community/gpt2` 的预训练 GPT-2
small，不用 mutable `main`：

| 项目 | 固定值 |
|---|---|
| revision | `607a30d783dfa663caf39e06633721c8d4cfcd7e` |
| loader | `AutoModelForCausalLM.from_pretrained(..., local_files_only=True)` |
| architecture | 12 blocks、12 heads、hidden 768、context 1024 |
| vocab / EOS | 50257 / 50256 |
| expected parameters | 124,439,808（tied lm head 不重复计数） |
| attention / cache | eager attention、`use_cache=false` |
| initialization | 8 learners 从同一 cached pretrained state 初始化，参数 SHA 必须相同 |

tokenizer 使用同一 repository/revision；`add_special_tokens=false`。模型 config、tokenizer
文件、权重文件和初始参数各自保存 SHA-256。架构、参数量、token ID 或 hash 不符时在训练
前 `ENV_FAIL`，不得自动换成别的 GPT-2 checkpoint。

### 6.3.2 WikiText-2 数据冻结

数据固定为 `Salesforce/wikitext` revision
`b08601e04326c79dfdd32d625aee71d232d685c3` 的
`wikitext-2-raw-v1`：

1. `train` 只用于 learner 训练，`validation` 只用于初始/最终冻结快照评估，`test` 在门禁开发和阈值调整中禁止使用；
2. 对每个 split 按原顺序读取 `text`；仅跳过 `text == ""` 的行，其他字符串不 strip、不 normalize；
3. 每个非空行以 GPT-2 tokenizer 编码（不加 special tokens），随后追加一个 EOS 50256；
4. 拼接 token stream 后切成不重叠的 512-token blocks，per-split 最后不足 512 的 remainder 丢弃；`labels=input_ids`，因此训练 batch 无 padding；
5. train block `j` 固定归 learner `j mod 8`；每个 learner 以 `seed=20260714+learner_id` 做确定性 epoch permutation，耗尽后才进入下一 epoch；
6. validation 使用全部 packed blocks、不 shuffle，由 learner-0 对 initial 与 final frozen version-vector snapshot 计算 token-weighted mean NLL；只要求 finite 并报告，首次 baseline 前不设置追溯性质量阈值。

冻结预处理的 expected counts 用于在提交前发现 tokenizer/data drift：

| split | source/nonempty rows | tokens before drop | packed blocks | remainder |
|---|---:|---:|---:|---:|
| train | 36,718 / 23,767 | 2,415,651 | 4,718 | 35 |
| validation | 3,760 / 2,461 | 249,750 | 487 | 406 |

train 的 8 个 shard block counts 必须为
`[590, 590, 590, 590, 590, 590, 589, 589]`。同时核对 config 中的 source parquet
SHA-256 和 token-stream uint32-le SHA-256；任一 count/hash 不符均不得提交 9N job。

预处理只运行一次，输出 dataset manifest、source file hashes、tokenizer hash、split block
counts、每 shard token count/hash。PBS 运行必须 `HF_HUB_OFFLINE=1`、
`TRANSFORMERS_OFFLINE=1`、`HF_DATASETS_OFFLINE=1`，不得在 8 个 learner 中动态下载或
重复预处理。

asset staging 是独立的单节点 compute job：先以 immutable revision 预取 model/tokenizer，
并只取 WikiText-2 raw 的 train/validation parquet；再运行一次 frozen preprocessing CLI。
staging 成功标志必须 visibility-last 发布，9N job 只接受 marker 中的 config SHA、source SHA、
tokenizer SHA、counts 与 8 shard hashes 全部匹配；它不是运行时自动下载 fallback。

### 6.3.3 批次与优化器

固定回归口径为 sequence length 512、per-device batch 4、gradient accumulation 1，故无
padding 时每个完整 optimizer step 处理 2,048 input tokens；GPT-2 内部 causal shift 后，
用于 loss 聚合的 target tokens 为 `4 × (512-1) = 2,044`。两种计数必须分别记录，proposal
weight 使用 source spec 规定的 processed-input-token 口径，loss aggregate 使用实际
loss-bearing target-token 口径。inner optimizer 固定为
`torch.optim.AdamW(lr=5e-5, betas=(0.9,0.999), eps=1e-8,
weight_decay=0.01)`，global grad norm clip 1.0，constant LR、无 warmup。compute 为 bf16，
optimizer state 和 outer merge accumulation 为 fp32。

precision、batch、sequence length、optimizer 或预处理任一变化都会产生新的 compatibility
key，不能与 `BASELINE-9N-GPT2-WT2-v1` 比 runtime。若 Miyabi 实测不支持该 bf16 路径，
必须在提交前写 ADR 并建立独立 fp32 baseline；不得在运行中 fallback。

GPT-2/WikiText-2 是固定的 loop 级系统回归 workload。它不替代 source spec 要求的
160M、M=4、真实 FS、≥1B-token Stage 1 long run，也不替代后续 160M/0.5–1B 性能与
matched-token 质量验收。

## 6.4 Loss 门禁

输入为每 learner 的结构化 loss events。默认算法：

1. 删除无效/缺失数据会直接失败，不插值掩盖；
2. 所有 loss 必须 finite；
3. 每 learner 至少有配置规定的最小 loss 点数；
4. 按 causal shift 后实际参与 loss 的 target tokens 计算 aggregate loss；input processed tokens 另作 proposal weighting 与吞吐计数；
5. 以滚动中位数或 EMA 平滑，参数在提交前冻结；
6. 比较 warmup 后初始 20% 与最终 20%；
7. 默认要求：
   - `median_final <= 0.99 * median_initial`；
   - aggregate robust slope < 0；
   - 任一 learner 最终窗口不得比初始窗口恶化超过 10%，除非当前 loop 预注册故障注入且 aggregate 仍通过；
8. NaN/Inf、持续爆炸、缺失 loss、模型未实际更新直接 BLOCKED。

本 profile 每 learner 至少 200 个 loss 点，前 20 点为 warmup；rolling-median window 为
20。训练 loss 是 PASS/BLOCKED 的下降判据。WikiText-2 validation initial/final NLL 是必需
证据但首次 baseline 仅作 finite/诊断检查，避免看完结果后设置阈值；若以后升级为 blocking
threshold，必须先 ADR、预注册并建立新 baseline。

阈值可以在 `S1-13` 前基于真实 1-node smoke 调整，但必须在首次 9 节点提交前冻结。之后改变阈值需 ADR，不能追溯性让失败 run 通过。

该门禁只验证训练“在发生且趋势正常”，不替代 Stage 4 matched-token eval。

## 6.5 Runtime 门禁

定义：

- `active_start`：9 个角色 ready 且 bootstrap 可读；
- `active_end`：syncer 成功发布 `global_cycle >= 10` 的完成 record，所有角色安全退出；
- queue wait、环境预置和用户等待不计；
- 数据从 shared cache 复制到 local scratch 是否计入由 profile 固定。

首次 `S1-13`：

- 根据 1-node 与 2-node smoke 在提交前冻结 absolute `runtime_budget_s`；
- run 成功后形成兼容基准：model、sequence length、batch、precision、F、H、dataset、Miyabi queue/node class、code path。

后续 loop：

```text
allowed_runtime =
  min(pre_registered_absolute_budget,
      max(1.50 × compatible_baseline,
          compatible_baseline + 300 seconds))
```

若 loop 故意注入 10s/30s visibility delay、kill/restart 或慢 FS，需在提交前定义 stage-specific budget 和排除/包含区间。不得作业后调整。

额外要求：

- 完成时间 < PBS walltime 的 80%；
- 非预期 heartbeat gap 不超过 2× 正常 fragment update interval；
- 无无限 polling、queue growth 或 pending stall；
- Stage 2 原有 95% goodput/2% pause 等更严格阈值优先。

## 6.6 门禁配置冻结

提交前保存：

- resolved config + SHA；
- role map；
- model/data/fragment map identities；
- model/tokenizer/dataset immutable revisions、source file hashes、tokenized shard hashes；
- sequence length、batch、gradient accumulation、optimizer、precision、RNG seeds；
- code commit；
- Miyabi skill commit；
- PBS script hash；
- runtime/loss thresholds；
- expected acceptance IDs；
- fault schedule（适用时）；
- reference baseline ID。

resolved config 还必须证明 gate config 与 loop profile 已完成 typed merge，所有
`fragment_count/offsets/Q/Q_fresh/S_max/lambda_s/grace/outer_optimizer` 占位符均已解析。

任何一项在 run 中改变，run 只能作诊断，不能作为 PASS 证据。

四个 `analysis/*.json` 必须是 machine-readable 的 PASS/FAIL 判定加关键数值，由
`S1-13` 起的 analyzer 直接生成。Checker 复核 gate 时按顺序读取 package validator
summary 与这四份 JSON；仅当 checksum、字段一致性或抽样复算失败时才展开 raw
logs/metrics。禁止以人工逐行核对 raw 输出替代 analyzer 判定，也禁止把整份 raw
日志注入 Checker 上下文。

## 6.8 Stage 特定 overlay

- Stage 1：Profile A，Q=M、fresh-only；建立基准。
- Stage 2：当前优化打开；同时报告 no-communication baseline/goodput。
- Stage 3：预注册 kill point；恢复后仍完成 global cycle 10。
- Stage 4：Profile B 或当前 stale feature；必须观察 stale eligibility/acceptance（相关 loop）。
- 所有 loop 仍使用相同基础 model/data profile，除非 loop 目标本身要求改变并已 ADR。

## 6.9 失败分类

- `TOPOLOGY_FAIL`：节点/角色/GPU 不满足；
- `ENV_FAIL`：module/dependency/cache/PBS；
- `PROTOCOL_FAIL`：版本、proposal、publication、quorum；
- `NUMERIC_FAIL`：oracle、NaN、loss；
- `PERF_FAIL`：预算/goodput/queue；
- `EVIDENCE_FAIL`：日志/manifest/哈希不全；
- `CHECKER_FAIL`：独立检查不通过。

失败 run 永久保留，不能改名为 pass。
